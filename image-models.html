这解释了“为什么可以改变分辨率”：只要新 H、W 经 VAE 下采样后形成合法 latent 网格，卷积路径或 patch 路径就能运行。但训练分布、位置编码范围、显存和图像质量会限制可用范围，模型卡写的推荐尺寸优先于理论最大尺寸。

同一个词不会直接变成像素。它先被编码为向量，再通过注意力改变 latent token。cross-attention 通常是 Q=image、K/V=text；joint attention 会让两类 token 在同一 attention 中交互；AdaLN 则把全局条件变成归一化后的通道调制。

4. U-Net、DiT、MMDiT：主干共同模块的区别

U-Net 路径

输入 latent 经过 DownBlock 降低 H/W，MidBlock 建模大范围关系，再由 UpBlock 恢复空间尺寸；skip connection 把高分辨率细节送回上采样。SDXL 详见 SDXL 结构页。

DiT 路径

latent 网格切成 image tokens，重复 Transformer block，再将 token 还原为 latent patch。图像 token 数 N=H'/p × W'/p，改变尺寸就是改变 N。

MMDiT 路径

文本 token 与图像 token 各自投影、归一化，在联合 attention 交互，再分别经过各自的 feed-forward/residual。SD3 的细节在 SD3 / MMDiT 页。

5. 训练目标、采样器和 CFG 是三个不同层次

层次 训练/推理输入 输出 说明
训练 target clean latent z0、噪声 z1、随机 t epsilon、v、x0 或 velocity 由具体模型的参数化决定
主干 forward zt、t/sigma、文本/图像条件 与 zt 同形状的预测 它是可训练网络
scheduler / ODE solver 当前 z、预测、时间步 下一步 z 它是数值更新过程，不是主干层
CFG conditional 与 unconditional 输出 组合后的 prediction 提高条件遵循，但 scale 过大可能过饱和

传统扩散常用加噪与去噪的 beta/sigma 时间表；flow matching 定义从噪声到数据的路径，让 Transformer 预测速度场，再用 Euler、Heun 等数值积分。FLUX 和 Qwen-Image 详页会分别说明自身的 pipeline 参数，不能把 scheduler 名称和 guidance 参数跨家族照抄。

8. 公共微调知识与模型入口

LoRA 把冻结矩阵 W 的更新写成 ΔW=(alpha/r)BA。图像生成常先冻结 VAE 和文本编码器，只训练主干 attention projection、MLP projection 或专用 condition projection；是否训练 text encoder、目标层名称和 rank 要按模型训练脚本确认。

SDXL 微调U-Net attention、feed-forward 和可选 text encoderSD3 微调双流/联合 attention 与 feed-forward targetFLUX 微调double/single stream qkv、out、MLPQwen-Image 微调Transformer 与 Edit 条件分支

每个详页都给出 named_modules() 核验片段；不要只根据网上的 target_modules 列表训练，因为 fused QKV、模块命名、checkpoint 版本和训练脚本都会改变可挂载位置。

图像微调的通用数据合同

文生图至少需要 image + caption；主体/风格任务还要 subject/style 标签；编辑任务需要 source、target、instruction，局部编辑再加入 mask；ControlNet 任务要保留原图与对应的 edge/depth/pose 控制图。按主体、来源或拍摄批次切分，去除近重复，记录宽高、裁剪、许可证、模型 revision 和验证提示。

训练时统一 VAE scaling、尺寸 bucket、caption 模板、随机 timestep/sigma 和预测 target；优先冻结 VAE/文本编码器做主干 LoRA，只有明确需要时才训练 condition projection 或 text encoder。验收至少包括未见主体/背景、不同宽高比、长短 prompt、非目标区域保持、文字准确率和基座旧能力，不能只用训练集图片或 loss 判断。
