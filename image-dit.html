模型详解 B / Diffusion Transformer

SD3 / DiT / MMDiT：从 latent patch 到联合注意力

DiT 把 latent 网格变成 token 序列，用 Transformer block 预测噪声、速度或 flow。SD3 类 MMDiT 的关键不是“把 U-Net 换成 Transformer”这么简单，而是文本流和图像流有各自的表示投影，再通过联合 attention 交互。

1. Patchify / Unpatchify

模块 输入 内部形式 输出
Patchify latent z [B,C,H′,W′] 按 p×p 切块；每块展平 C·p²，再 Linear 投影 image tokens [B,Nimg,D]
position token index / 2D coords RoPE 或其他空间位置变换 带位置的 token
Unpatchify pred tokens [B,Nimg,C·p²] 还原二维网格并 reshape pred latent [B,C,H′,W′]

例如 latent 128×128、patch 2 时 Nimg=4096；latent 256×256 时 Nimg=16384。空间面积翻倍不是 token 翻倍，而是约四倍；全局 attention 的 pair 数还会平方增长。

3. SD3 MMDiT 的双流与联合 attention

双流结构给图像 token 和文本 token 不同的 Linear、Norm 和参数空间： 图像侧用 to_q/to_k/to_v 与 to_out.0，文本侧用 add_q_proj/add_k_proj/add_v_proj 与 to_add_out。在 SD3 / Diffusers 的实现里，两流先各自投影到 同一个 head 维度，然后 torch.cat([q_img, q_txt], dim=2)（序列维，即 [B,heads,N_img,64] 与 [B,heads,N_txt,64] 拼成 [B,heads,N_img+N_txt,64]，K/V 同理），做一次 softmax(QKᵀ/√d)V，再把结果按 hidden_states[:, :residual.shape[1]] 与 hidden_states[:, residual.shape[1]:] 拆回图像段和文本段， 各自经过 out projection 与 residual add，然后各走自己的 FFN。 这样做的目的是让多模态交互更灵活，而不是把 text embedding 直接复制到每个图像 token，也不是在通道维拼接条件。

4. 文本编码器和多路条件

不同 checkpoint 会组合 CLIP、T5 等文本编码器，输出 per-token hidden 与 pooled embedding。pipeline 可能把 pooled embedding 作为全局条件，把序列 hidden 送入 joint attention；还可能加入图像 embedding、尺寸/裁剪信息或编辑参考。必须从具体 pipeline 的 encode_prompt 和 transformer forward 参数确认，而不能只看模型名称。

条件 典型输入 典型输出 注入位置

pooled text text hidden [B,Dt] time/AdaLN/global projection
参考图 RGB 或 image embedding image tokens [B,Nref,D] joint attention/adapter
timestep/sigma scalar [B] condition [B,D] AdaLN、gate 或 block modulation

5. Flow Matching 训练和推理

取数据 latent z_data（也就是 VAE 编码后的干净 latent）和噪声 eps ~ N(0,I)，在时间 t ∈ [0,1] 上定义直线路径 z_t = (1 - t) · z_data + t · eps，该路径的真实速度是 u = dz_t/dt = eps - z_data（噪声减数据；写成 “z1 − z0”时容易把谁是噪声弄反，必须按具体实现核对）。Transformer 输入 z_t、t 与条件 c，输出 vθ(z_t,t,c)；训练最小化 ||vθ(z_t,t,c) - (eps - z_data)||²。推理从噪声出发，用 Euler/Heun 等 ODE solver 按 sigma 序列逐步积分。solver 的 step 数影响速度与质量，但它不是 Transformer 的层，也没有可学习参数。

阶段 输入 输出
训练路径 z0、z1、t zt、target velocity u
DiT forward zt、t/sigma、text/image condition vθ 与 zt 同形状
solver step zt、vθ、dt zt+dt·vθ

6. DiT LoRA 位置和最小示例

常见目标包括 attention 的 to_q/to_k/to_v/to_out、双流/联合 attention 的投影，以及 MLP 的 fc1/fc2 或 proj_in/proj_out。具体名称要打印模块树。VAE 通常冻结，text encoder 是否训练由官方脚本决定。

DiT / MMDiT 的数据和训练选择

T2I 数据是一行一个图像路径和 caption；编辑任务必须保留源图、目标图、指令和 mask；文字渲染任务要单独收集不同字体、语言、字号和长短文本。按主体、艺术家或来源分组切分，训练前检查 caption 是否描述画面而不是复制文件名，并固定 VAE、text encoder、latent scaling 和尺寸桶。

任务 数据字段 推荐训练 主要验收
风格/主体 LoRA image、caption、subject/style、size、license 冻结 VAE/文本编码器，训练 image stream 与 joint attention LoRA 主体、风格、构图和 prompt 遵循
文字/布局 image、精确文字转写、区域/布局标注 扩大 attention 与 MLP target；必要时全量或 adapter 微调 字符准确率、位置、字号和不同语言泛化
编辑/参考图 source、target、instruction、reference、mask 条件投影或 image stream adapter；不要把源图误当 caption 保留区域、修改区域和边界融合

Flow Matching/rectified-flow 模型通常从图像 latent z1 与噪声 z0 采样时间 t，构造 zt 和速度 target，再以 MSE 更新 transformer；推理时 solver 步数不是训练 epoch。先用 image-only LoRA 跑通，再决定是否训练文本条件投影；每次实验保存 patch/packing、sigma schedule、solver、rank/alpha 和固定 seed，比较未见宽高比与长文本。
