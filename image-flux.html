模型详解 C / Flow Transformer

FLUX：double-stream、single-stream 与 flow matching

FLUX 的核心不是一个模糊的“多模态 DiT”。一个典型 FluxTransformer 先让图像 token 和文本 token 经过各自的 double-stream block，再把两种 token 合并到 single-stream block 中继续处理，最后只从图像 token 预测 latent 的速度更新。具体层数和模块名以 checkpoint 的 config 和实现为准。

FluxTransformer = FLUX 的扩散 Transformer 主干double-stream = 图像/文本各自保留 streamsingle-stream = 合并 token 后共用 blockflow matching = 预测从噪声到数据的速度场T5 = 文本序列语义条件CLIP = pooled/序列视觉语言条件RoPE = Rotary Position EmbeddingMLP/FFN = attention 后的逐 token 通道变换LoRA = 低秩参数增量

3. 图像路径：VAE latent 如何变成 image tokens

模块 输入 内部形式 输出
VAE Encode（I2I） RGB [B,3,H,W] 卷积 encoder + scaling scaled latent [B,C,H',W']
Noise init（T2I） seed、H、W 生成随机 latent noisy latent
Patchify / linear latent 网格 局部 patch 展平和线性投影 image tokens [B,Nimg,D]
Unpatchify 预测 image tokens 按二维坐标还原 patch latent update [B,C,H',W']

FLUX 的 latent 是 16 通道，但 pipeline 在送进 transformer 之前会先打包： [B,16,128,128] → [B,4096,64]（16×4=64），再由 x_embedder 投到 3072。位置编码同时使用 img_ids （(0,h,w) 三维坐标）与 txt_ids（文本位置），并在序列维拼接后送入 MM-RoPE：ids = cat((txt_ids, img_ids), dim=0)。它不是把每个像素当 token，而是先经过 VAE、pack 与线性投影，所以尺寸变化主要表现为 N_img 变化。

MLP 对每个 token 的最后一维做升维、激活/门控、降维，不直接在 H×W 邻域上卷积。attention 负责跨 token 信息交换，MLP 负责通道表征变换。注意区分：两种 token 之间是序列维 concat + attention， 残差路径才是逐元素相加。实现可能融合 gate 或使用不同命名，要以打印出的 模块树为准。

6. Flow matching：训练预测速度，推理用 solver

设数据 latent 为 z_data（VAE 编码得到的干净 latent）、噪声为 eps ~ N(0,I)，在线性路径上有 z_t = (1-t)·z_data + t·eps，路径速度是 u = eps - z_data（噪声减数据；写成“数据减噪声”会让 sampler 朝反方向走）。Transformer 接收 z_t、t（以及可选 guidance）与文本条件，输出 v_theta，训练常用 ||v_theta - u||²。推理从噪声出发，Euler/Heun 等 solver 根据 v_theta 差分更新 packed latent。

组件 输入 输出 训练参数
path construction z0、z1、t zt、target velocity 否
FluxTransformer zt、t/sigma、text、guidance velocity 是
flow scheduler current z、velocity、dt next z 通常否
VAE decode 最终 latent RGB 通常冻结

7. FLUX 为什么支持多个分辨率

输入 H×W 经过 VAE 变成 H'×W'，再按 patch size p 变成 Nimg=(H'/p)×(W'/p) 个图像 token。序列长度可以变化，RoPE 使用坐标而不是固定二维参数表，所以通常能处理多种长宽比。限制来自 VAE 对齐倍数、patch 对齐、训练尺寸分布、attention 显存和官方尺寸建议。

手算例子

以空间压缩 8 倍、pack 为 2×2 为例：1024×1024 → 128×128 latent → pack 后 64×64 = 4096 image tokens；1664×928 → 208×116 latent → 104×58 = 6032 tokens（若按未打包的 patch 计数会得到不同数字，写文档时必须说明是否已 pack）。面积变大时 attention、激活和 VAE 解码成本都会增加。

8. FLUX LoRA：哪些层可以调

常见候选是 double-stream 和 single-stream 内的 attention q/k/v、attention output projection，以及 MLP 的输入/门控/输出 projection。通常冻结 VAE；文本 encoder 是否训练要看显存、数据量和官方脚本。不同变体可能使用 fused QKV 或不同模块树，不能只复制 SDXL 的 to_q 名称。

候选位置 原始输入 LoRA 影响的输出 适合表达
double-stream q/k/v image/text token attention Q/K/V 条件对齐、主体/风格关系
double-stream out attention context stream hidden 融合强度和残差更新
single-stream q/k/v/out 拼接 token 联合序列交互 构图、文字与物体关系
MLP projection token hidden 通道非线性更新 风格、纹理和概念偏移

FLUX 的数据格式、训练方式和边界

普通风格/主体训练使用图像加 caption；FLUX 的文字能力还需要精确转写、字体/语言多样性和文字区域样本。编辑或参考图任务要成对保存 source、target、instruction、参考图和 mask。每条样本记录尺寸、裁剪、长宽比 bucket、来源许可和 split，并按主体或来源去重。

目标 数据 训练方案 验收
主体/风格 多角度图片 + caption，通常 50—1000 张 优先 image/text stream LoRA；显存足够再扩大 target 主体身份、风格强度、提示词泛化和旧能力
文字渲染 图像、精确文本、语言/字体/区域 attention + MLP LoRA；保留不同字体验证集 字符准确率、布局和不同长度文字
编辑/参考 source/target/instruction/reference/mask 条件投影或 adapter；不要只训练单流 MLP 修改区域、非目标区域保持与构图

训练前先冻结 VAE、CLIP/T5 和不需要的 stream，只在打印出的真实 q/k/v、out、MLP projection 上挂 LoRA；flow-matching loss 使用随机 t/sigma 的 latent 速度 target。FLUX 变体可能有 fused QKV、不同文本编码器和许可证限制，不能照搬 SDXL target 名称；验收要覆盖不同宽高比、长 prompt、文字、主体未见角度和 LoRA 权重插值。
