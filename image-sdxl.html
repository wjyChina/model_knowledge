SD 1.5 / SDXL：U-Net 每个模块的输入与输出

这里把 SD 1.5 与 SDXL 的 Text Encoder、VAE、U-Net、Scheduler 四条数据路径展开成可追踪的顺序数据流，并把两者的条件编码分开画： SD 1.5 只有一个 CLIP-L 文本编码器（U-Net cross_attention_dim=768，没有 pooled 文本条件）；SDXL 使用 CLIP-L + OpenCLIP bigG 两个文本编码器（cross_attention_dim=2048）， 并额外把 pooled embedding 与 added time/size ids 送入 U-Net。把 SDXL 的双编码器路径当成 SD 1.5 的路径是最常见的错误。 本页形状示例取自两个官方 checkpoint 的 config；具体层数、skip 数量仍以所选 checkpoint 为准。

c_text 到底是什么：定义、形状、去向

c_text 是“逐 token 的文本条件张量”，由上一步的文本编码器 产生，不是 prompt 字符串，也不是单个向量： SD 1.5 为 [B,77,768]（CLIP-L 的 hidden_states[-2]）；SDXL 为 [B,77,2048]（CLIP-L 768 维与 bigG 1280 维沿最后一维 concat(channel)）。它被送到 U-Net 中每一个配置为 cross-attention 的 block（SDXL 的 down_block_1、down_block_2、mid_block 与 up_block_0/1/2；down_block_0 与 SD 1.5 的 down_block_3 没有 cross-attention）。在每个这样的 block 里，当前空间 feature F [B,C,H_s,W_s] 展平成视觉 token 作为 Q，c_text 经该 block 自己的 to_k/to_v 线性层得到 K,V，计算 softmax(QKᵀ/√d)V，再 reshape 回空间 feature 并逐元素相加回该 block 的输出。文本只在循环外编码一次；所谓“每步重复”指的是这些 cross-attention 在每一个 denoising step 里都会重新读取同一份 c_text（读取次数 ≈ 含 cross-attn 的 block 数 × 采样步数）， 而不是每一步重新编码。

第 t 步的数据 在 U-Net 中的去向 是否下一步还用
z_t 作为当前带噪 latent，经过 Down/Mid/Up 得到预测 scheduler 生成新的 z_{t-1} 后继续用
c_text 在 cross-attention 里生成 K/V，调制视觉 feature 同一 prompt 通常每一步复用并重新参与 attention
t 与 added time/size ids 变成 time/ADM embedding，注入 ResNet 或条件层 每一步的 t 会变；尺寸/裁剪条件通常保持该样本不变

文本 encoder 通常冻结。它只需在 pipeline 开始时把 prompt 编码成 c_text；但 c_text 会随每个 denoising step 传给 U-Net。每个含 cross-attention 的 block 各有一套 to_k/to_v：Q = Wq · visual_feature、K/V = Wk/v · c_text，然后把 softmax(QKᵀ/√d)V 的结果与视觉 feature 逐元素相加。所以“文本路径在左边”不是只连到第一次输入，而是同一份条件在每一步、每个相关 stage 被重新读取。SDXL 还有第二条条件路径：pooled [B,1280] 与 timestep embedding 逐元素相加（形状都是 [B,1280]），再和 6 维 added time/size ids 拼成的 2816 维向量一起 注入每个 ResNet 的 scale/shift。

2. VAE：像素与 latent 的接口

路径 输入 主要模块 输出
Encode RGB x [B,3,H,W] Conv stem → 多个 ResNet/downsample → mean/logvar → sample 或 mean z [B,4,H/8,W/8]（SDXL 常见约定）
Scale z pipeline 使用模型特定 scaling factor 送入 U-Net 的 scaled latent
Decode clean z [B,4,H′,W′] 反 scaling → mid ResNet → upsample blocks → Conv RGB [B,3,H,W]

VAE 的下采样倍数决定 latent 网格。SDXL 常见空间压缩比例是 8，因此 1024×1024 像素约对应 128×128 latent；768×1024 则约对应 96×128 latent。 输入 H/W 通常需要符合下采样倍数；改变 latent H′/W′ 就能改变输出分辨率，但训练分布和 attention 成本仍限制质量。

3. U-Net 一次 forward：Down 保存 skip，Up 逐级取用

下图以 SDXL（1024×1024 → latent 128×128）为例写出真实张量流。橙色箭头是 skip feature 的搬运：Down block 的输出既继续向下传播，也被保存下来送给对应 Up block；Up block 内部先做 torch.cat([up_input, skip], dim=1)（通道维拼接，要求空间尺寸一致）， 再由 conv_shortcut 投影回该层通道宽度，之后才与该层内部 ResNet 的 残差路径做逐元素相加。这两步是不同运算，不能都写成 “+”。

4. timestep、scheduler 与 CFG：一次 denoising step 的完整输入输出

训练先从 clean latent z0 和噪声 epsilon 构造 zt；U-Net 接收 zt、时间 embedding 和 text context，预测 epsilon 或 v。推理从纯噪声 z_T 开始，下面的步骤会重复 N 次：当前 latent z_t、当前 timestep t、同一份文本 context c_text 和尺寸/裁剪等 SDXL added condition 一起进入一次 U-Net forward；U-Net 在 Down/Mid/Up 的每个相关 block 使用它们，输出 model_output_t；最后 scheduler.step 才把它变成下一状态 z_{t-1}。文本条件、timestep 和可选控制 residual 因此通常是每一步都输入，不是只在第一次输入。CFG 还会对同一个 z_t 分别跑 unconditional 与 conditional 两次 forward，再组合 eps = eps_u + scale * (eps_c - eps_u)；这是“有条件预测减无条件预测再放大”的 代数式，不是把两个 latent 相加。这就是为什么 CFG 通常近似增加一倍 U-Net 计算。

组件 输入 输出
noise scheduler 训练的 z0、epsilon、t；推理的 timesteps/sigmas 训练 zt；推理初始化 zT 与每一步的时间表
U-Net 每一步 zt、t、text context、added time/size ids、可选 control residual model_output_t：noise/v prediction，与 zt 同形状
scheduler.step model_output_t、t、zt 下一步 zt-1；不负责理解 prompt
CFG uncond output、cond output、scale guidance output，与 latent 同形状

5. LoRA 在 SDXL 挂哪里

常见 attention LoRA target 是 to_q、to_k、to_v、to_out.0；更高容量训练会加入 U-Net 中的 feed-forward projection，部分脚本也支持 text encoder LoRA。VAE 通常冻结。准确模块名要从 unet.named_modules() 和官方训练脚本确认。

Python · 找 SDXL 候选层 
for name, module in pipe.unet.named_modules():
    if name.endswith(("to_q", "to_k", "to_v", "to_out.0")):
        print(name, type(module).__name__)

训练图片通过 VAE Encode 得到 latent；对随机 t 加噪；U-Net 预测 target；loss 只对预测和 target 比较。LoRA 梯度更新 attention/MLP 的 A/B，不更新原始 U-Net W。

SDXL 要准备什么数据，应该怎么训练

先按目标区分数据：主体身份用同一主体的多角度、多距离、多光照图片；画风用不同内容但风格稳定的图片；构图或产品包装用带明确 caption 的完整画面；局部重绘还要增加 source/target/mask 三元组。每张图记录文件路径、caption、宽高、裁剪、主体标签、许可证和 split，按主体或拍摄批次切分，避免同一张图的近重复同时进入训练和验证。

目标 推荐样本 训练方式 冻结范围与验收
主体/风格 20—500 张多样图片 + 精确 caption U-Net LoRA；主体可用 DreamBooth 类 prior preservation 冻结 VAE；先只训 attention，验证身份、提示遵循和未见角度
构图/产品 成对或带布局描述的图文样本 U-Net LoRA/全量微调；必要时加 ControlNet 保留不同背景与负面场景，检查位置、比例和文字
局部编辑 source、target、mask、instruction 四元组 inpaint U-Net LoRA 或 ControlNet 分支 mask 外区域保持率、边缘融合和编辑成功率

{"source":"edit/in_004.png","target":"edit/out_004.png","mask":"edit/mask_004.png","instruction":"把杯子改成红色，保留手和桌面","split":"validation"}

训练目标仍是随机 timestep 的 epsilon/v prediction：VAE 和文本编码器先冻结，图片 latent 加噪后只更新选定的 U-Net LoRA；小数据从 rank 4—16、低学习率和少量 epoch 开始，记录 base revision、分辨率桶、caption 模板、seed、rank/alpha、训练/验证 loss 和固定提示图。不要只看 loss，必须与 zero-shot 基座比较主体一致性、风格迁移、文字、负面提示和旧能力保持。

6. 最小 pipeline 示例

Python · Diffusers SDXL 
import torch
from diffusers import DiffusionPipeline
pipe = DiffusionPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0",
    torch_dtype=torch.float16, use_safetensors=True
).to("cuda")
image = pipe(
    "a technical cutaway diagram of a transformer block",
    width=1024, height=1024, num_inference_steps=30,
    guidance_scale=5.0, generator=torch.Generator("cuda").manual_seed(7)
).images[0]
image.save("sdxl.png")
