并行与调度：每张卡到底在做什么

本页用同一套记号说明 DP、TP、PP、EP、SP/CP、FSDP/ZeRO，以及服务端的 Prefill/Decode、连续批处理和投机解码。每节都给出设备分工、输入输出、通信原语、启动例子和失败条件。

1. DP / DDP：复制模型，切数据

DP = Data Parallelism，数据并行DDP = DistributedDataParallel，分布式数据并行rank = 一个训练进程all-reduce = 全部 rank 汇总并同步 tensor

假设 2 张 24 GB GPU 都能放下完整模型。rank 0 和 rank 1 各加载一份 W，数据集被 DistributedSampler 切成不同 microbatch。每个 rank 的 forward 输入不同，输出各自 loss；backward 产生本地梯度 G0、G1，DDP 在梯度桶上执行 all-reduce，二者都得到平均梯度，再各自执行同样的 optimizer step。

两卡都得到相同的 W′；输入样本不同，参数更新相同
对象输入输出
每个 rank完整模型 W、不同 microbatch本地 loss、梯度 Gᵢ
all-reduce各 rank 同形状梯度每个 rank 相同的平均梯度
global stepmicrobatch × rank 数 × 累积步数一次参数更新
Shell · DDP 训练
CUDA_VISIBLE_DEVICES=0,1 torchrun --standalone --nproc_per_node=2 \
  train.py --per_device_train_batch_size 1 --gradient_accumulation_steps 8

适用：模型单卡放得下、目标是训练吞吐。不适用：模型单卡放不下；DDP 会复制完整权重。

2. TP：切一层矩阵，单个请求跨卡

TP = Tensor Parallelism，张量并行column parallel = 按输出列切 Linearrow parallel = 按输入行切 Linearall-reduce / all-gather = 层内同步

对 Y=XW，column parallel 将 W=[W0|W1] 分到两卡，各卡得到 Y0=XW0、Y1=XW1，输出维拼接，通常需要 all-gather。row parallel 将 W=[W0;W1]、输入也切成 [X0,X1]，各卡得到部分输出，最后 all-reduce 求和。Attention 中通常按 heads 或 projection 维度切。

适用：高速 NVLink/NVSwitch、单层或单卡权重放不下、降低单请求 latency。PCIe 卡频繁 all-reduce 可能比单卡更慢。

3. PP：切层，激活沿流水线流动

PP = Pipeline Parallelism，流水线并行stage = 连续的一段层microbatch = 流水线小批次pipeline bubble = 等待填充/排空造成的空闲

把 32 层模型切成 2 个 stage：GPU0 放 0—15 层，GPU1 放 16—31 层。activation A0 经 GPU0 得到 A1，通过 point-to-point send/recv 发给 GPU1；反向把梯度发回。把 batch 切成多个 microbatch 后，GPU0 可以处理后续 microbatch，同时 GPU1 处理前一个。

时间 →
GPU0 stage 0mb0mb1mb2mb3
GPU1 stage 1等待mb0mb1mb2
microbatch 越少，bubble 占比越高
边界发送接收
forwardGPU0：hidden activation [mb,S,d]GPU1：接收 activation，继续后半模型
backwardGPU1：对 activation 的梯度GPU0：继续反传到前半模型

适用：模型层数太多、跨节点网络比层内 TP 更适合。代价：stage 不均、send/recv 等待、bubble 和激活通信。

4. EP：MoE 专家如何跨卡调度

MoE = Mixture of Experts，混合专家EP = Expert Parallelism，专家并行router = 专家路由器top-k = 每 token 选择 k 个专家capacity factor = 专家容量系数

token 先经过 router 得到 scores，选 top-k 专家。若 expert 0、1 在 GPU0，expert 2、3 在 GPU1，token 通过 all-to-all 发往目标 GPU；专家 MLP 处理后再发回。router 权重对多个 expert 输出加权求和，并可加入 load-balancing loss。

EP 的瓶颈通常是 all-to-all 网络、专家负载不均、capacity overflow 和跨节点尾延迟。总参数、激活参数和通信量要分开报告。

5. FSDP / ZeRO：切状态，临时重组参数

FSDP = Fully Sharded Data ParallelZeRO = Zero Redundancy Optimizerparameter shard = 参数分片optimizer state = 优化器状态
方案每卡保存关键通信解决什么
DDP参数 + 梯度 + optimizer 全副本all-reduce 梯度增加吞吐
ZeRO-1参数/梯度副本，optimizer 分片同步状态减少 optimizer memory
ZeRO-2参数副本，梯度/optimizer 分片reduce-scatter 梯度减少梯度与 optimizer
ZeRO-3 / FSDP参数/梯度/optimizer 都分片forward all-gather，backward reduce-scatter训练超单卡模型

FSDP 不是把一层永远平均放在卡上，而是在执行模块前临时 all-gather 参数，执行后重新分片。峰值显存仍要预算当前模块、激活和通信 buffer。保存 checkpoint 时要明确 full state dict 还是 sharded state dict。

6. 服务调度：Prefill、Decode 和连续批处理

Prefill = 输入预填充Decode = 自回归生成TTFT = Time To First Token，首 token 时间ITL = Inter-Token Latency，token 间延迟continuous batching = 连续批处理chunked prefill = 分块预填充speculative decoding = 投机解码

Prefill 并行处理整个 prompt，建立 KV；Decode 每步追加新 token，受串行依赖影响。调度器每轮决定请求、token budget、KV block 和 kernel。连续批处理允许新请求加入、旧请求退出，不必等待静态 batch 全部结束。

请求 APrefill 1000D D D D
请求 BD D新请求 PrefillD D D
请求 CPrefill 200D D D D D
每个时间片混合多个请求的 decode；调度器管理 KV、抢占、公平性和尾延迟
方式优点代价
static batching简单，kernel 规整短请求等待长请求
continuous batching高并发、高吞吐KV 和公平性复杂
chunked prefill长 prompt 分块，不阻塞 decode需要调 chunk 大小
speculative decodingdraft 一次提多个，大模型批量验证接受率低时收益消失

服务验收同时报告 TTFT、ITL、P50/P95、总 tokens/s、并发数和峰值 KV 显存。
