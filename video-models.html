视频模型详解 / 功能领域与主干

视频生成：先按任务，再按模型和显存

视频模型共享“文本/图像条件 → 时空 latent → 视频主干 → 时空 VAE 解码”的大框架，但时间压缩、3D patch、空间/时间 attention、文本编码器、MoE 专家和长视频记忆策略不同。本页先讲公共结构，再按 T2V、I2V、编辑、长视频、音频/数字人分区，并给出代表模型的结构边界。

2. 文本生视频 T2V：没有源画面时怎样建立动作

T2V 输入是 prompt、尺寸、帧数、FPS、seed 和采样参数。文本 encoder 输出序列条件，视频主干从随机时空 latent 开始；每个 denoise/flow step 同时更新多个帧的 latent。动作合理性取决于训练视频中的运动分布、时间 attention 和文本条件，而不是把图像生成重复 T 次。

Wan 2.2开放权重/代码，覆盖 T2V、I2V、TI2V；部分版本使用高低噪声专家。HunyuanVideo / 1.5潜视频 Transformer 路线，按版本提供 T2V/I2V 和不同资源配置。CogVideoX3D VAE + video Transformer，T2V/I2V 生态和训练代码较完整。LTX-Video / LTX-2时空压缩 Transformer 路线，后续版本扩展音视频能力。MiniMax H3统一文本、图像、视频、音频上下文；H3-Omni-Transformer 联合预测视频与音频 latent。

4. V2V、重绘和局部视频编辑

V2V 通常先把源视频编码到时空 latent，再按 strength/噪声起点重采样；编辑指令、mask、参考图或结构控制作为额外条件。mask 必须与时间和空间 latent 对齐，逐帧独立 mask 不能保证边界连续。视频编辑的质量门控至少包括身份、运动、边界接缝、闪烁、字幕和音画同步。

模块 输入 输出 工程要点
video processor 帧序列、FPS、裁剪 规整的视频 tensor 固定帧率、尺寸、色彩和帧顺序
3D VAE encode [B,3,T,H,W] [B,C,T',H',W'] 时间 padding/压缩会影响首尾
mask/control encoder mask、深度、姿态、边缘 latent/token condition 空间和时间对齐
video transformer noisy source latent + instruction 更新 latent strength 越高，偏离源片越多

5. 长视频与续写：一次生成长片不是默认能力

长视频通常由短窗口、重叠上下文、参考帧/记忆、分镜和后期剪辑组成。FramePack 类方法强调按上下文管理帧序列；一般的视频模型也会受训练片段长度、时间位置编码、显存和误差累积限制。制作流程应先生成短镜头，锁定角色参考与镜头语言，再做续写和拼接。

FramePack低资源长序列工作流与上下文窗口，重点是续写和内存管理。AnimateDiff给图像扩散模型注入运动模块，适合动画/风格探索，不等于完整视频基础模型。

续写的输入输出

输入：上一段尾帧/尾部 latent、角色参考、下一镜 prompt、目标时长；输出：新窗口的帧序列和可用于下一次续写的尾部上下文。每次生成后检查身份、光照、相机轴线和运动速度，再决定是否继续。

6. 音频驱动、口型和数字人

音频/数字人通常不是单一 T2V 模型直接完成，而是视频生成、语音识别/音频特征、口型或动作驱动、声音合成、剪辑合成的多模块工作流。输入可能是音频波形 [B,T_audio]、mel 特征 [B,T_mel,F]、人脸/身体参考和文本；输出是同步的脸部/身体帧与音频。必须评估肖像、声音和训练数据授权。

模块 输入 输出
ASR / text audio waveform 文字或音素时间轴
audio encoder audio/mel audio tokens/features
face/body driver 参考身份 + audio features landmark/motion condition
video generator condition + latent 视频帧
mux / post 视频 + 音频 封装后的 MP4/WebM

9. 视频 LoRA：通用目标层与每种模型的核验方法

视频 LoRA 原型通常冻结 3D VAE 和文本 encoder，只在 video transformer 的空间/时间 attention q/k/v/out、MLP projection、motion module 或 condition projection 上训练。若模型有高低噪声专家或多个分支，必须明确训练哪个 expert、是否共享 adapter，以及推理时如何加载。

每个视频模型的数据和训练方式

视频微调不能把图片 LoRA 直接扩展到视频。每条样本至少追踪视频文件、caption、FPS、帧数、裁剪、音频采样率、主体/动作标签、参考帧和许可证；训练/验证按视频或主体切分，不能按帧随机切分，否则相邻帧会泄漏。先固定短 clip 和尺寸 bucket，验证通过后再增加时长或分辨率。

模型/家族 数据应包含 优先训练方式 专项验收
Wan 2.2 T2V clip-caption；I2V 还要首帧/参考图；记录高低噪声 expert 按官方脚本给的模块挂 video-transformer LoRA；确认两个 expert 是否分别训练 动作、主体、低/高噪声阶段和不同镜头长度
HunyuanVideo / 1.5 短视频、精确 caption、FPS/分辨率；I2V 加源图和起始帧 冻结 VAE/文本编码器，训练时空 attention/MLP LoRA 或官方 adapter 运动幅度、闪烁、镜头和未见主体
CogVideoX 固定帧数 clip + caption；I2V 成对 source clip/target clip 优先 temporal/spatial attention LoRA；3D VAE 不随意解冻 跨帧身份、动作连续性、首尾帧和文本遵循
LTX-Video / LTX-2 视频 caption；LTX-2 还要音频、采样率、音画时间对齐 分别核对 video/audio 分支和官方训练入口，必要时只训 motion/adapter 运动、音画同步、语音/声音质量和长短片段
AnimateDiff 图像底模对应的短动画 clip、帧级 caption 或运动标签 冻结 2D base U-Net，主要训练 motion module；不要混用不兼容底模 动作循环、风格一致、单帧画质和闪烁
FramePack 长视频拆成带重叠上下文的片段、首尾帧/记忆窗口和镜头标签 先核对上下文/分块机制；通常训练适配器而非把拼接逻辑当 LoRA 层 续写接缝、长程身份、镜头切换和误差累积
MiniMax H3 视频、音频、文本和条件组合；音频采样率、时长、同步标注 先分离 video/audio/shared/condition target，再决定单模态或联合 LoRA 动作、音画同步、语音清晰度、跨模态条件遵循

训练目标依模型而定：扩散模型在随机噪声时间步预测 epsilon/v，flow 模型预测 velocity；时空 VAE 先把 clip 压成 [B,C,T',H',W']，然后对空间和时间 token 做预测。显存不足时先减少帧数、分辨率和 batch，使用梯度检查点和 LoRA；不要用单帧 FID 代替视频验收。每次实验固定 sampler/solver、帧数、FPS、seed、LoRA 权重和模型 revision，保存训练集之外的主体、动作、镜头、闪烁和同步回归集。

候选层 输入 输出 学习的变化

temporal attention 跨帧 tokens 时间 context 动作、身份、镜头运动
