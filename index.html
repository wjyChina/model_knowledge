01 / 部署与并行

先算资源账，再挑模型

显存不是只装权重：KV cache、激活、临时缓冲、框架开销和训练状态会争同一块空间。首先分清“容量问题”和“吞吐问题”。

推理的五项账

权重下界约为参数量 × 每参数位数 ÷ 8；真实占用还包括量化分组 scale/zero-point、未量化层和对齐。10B 参数的 4-bit 裸权重约 5 GB（十进制），绝不意味着 6 GB 显卡一定跑得动。KV cache 对标准 decoder 的近似为 2 × 层数 × KV heads × head dim × 当前缓存 token 数 × batch × 每元素字节；GQA/MQA 减少 KV heads。并发、长上下文会把它推高。

碎片与 CUDA

训练时还需梯度、优化器状态与保存的激活。以常见混合精度 Adam 全参数训练为例，经常用 约 12—20+ bytes/参数做粗估（参数副本、梯度、Adam 一二阶矩与实现差异），再加激活；不能把推理 4-bit 文件大小直接乘一倍当训练预算。LoRA 只减少可训练参数的梯度/优化器，不会让基座、激活、KV 自动消失。

权重容量估算器

仅估权重裸容量与规划余量；不推断速度，也不替代模型卡。

按硬件类别决策

这张表先回答“当前硬件能稳定跑什么”，再回答“应该选哪种模型格式”。判断顺序是：先看权重和运行时余量能否放下，再看上下文、并发或视频帧带来的动态显存，最后用实际吞吐和延迟验证方案，而不是只按显卡名称选模型。

02 / 部署与并行

量化：压缩什么，牺牲什么

量化把连续数值映射到有限整数/浮点码本。它先解决容量与带宽；速度和质量收益须由硬件内核、模型和任务实测。

从线性映射开始

对一组权重可写 $q = \mathrm{clip}(\mathrm{round}(x/s) + z,\ q_{\min},\ q_{\max})$，反量化 $x_{\text{hat}} = s\,(q - z)$。对称量化通常 z=0；per-channel/per-group 比全张量共享尺度更能照顾离群值，却要保存更多元数据。W4A16 是权重 4-bit、激活 16-bit；W8A8 两者都 8-bit，硬件支持时更可能有完整低精度 GEMM。KV cache 精度是另一个独立旋钮。

版本与质量的实际判断

Qwen、Llama、Gemma、Mistral、DeepSeek、gpt-oss 等家族中，部分官方或社区发布 BF16/FP8/GGUF/GPTQ/AWQ 变体；“有量化版”是具体模型修订、仓库和转换工具的属性，并非整个家族的永久属性。优先官方模型卡，核对量化者、基座 commit、tokenizer/chat template、许可证与推理框架。社区转换须自行复测。

质量通常随比特数降低而更脆弱，但损失不是固定百分比：事实问答、代码、数学、长上下文、工具调用和多语言可能出现不同退化。相同名义 4-bit 的 group size、校准集和敏感层保留方式也不同。做 FP16/BF16 基线 → 8-bit → 4-bit 配对评测，比较准确率/通过率、拒答与格式遵循，且记录吞吐和显存；不要只看通用榜单。

推理优先

先用受支持的 GGUF 或 AWQ/GPTQ/FP8 检查模型适配，再测 kernel。低比特主要省权重带宽；长上下文仍受 KV 限制。

微调优先

QLoRA 常用 NF4 基座 + BF16 计算 + LoRA；多数 PTQ checkpoint 不能直接拿来继续全参数训练。

训练多卡：梯度、状态与模型分片

推理 TP 并不是训练并行的全部。训练要同时安排参数、梯度、优化器状态与激活，还要处理同步语义。

实验专题 / 多卡

多卡不是魔法：通信原语与拓扑验收

多卡性能取决于计算、通信和同步等待的比例。先理解通信原语，再用硬件拓扑和 profiler 证实瓶颈，不要把 GPU 数量直接等同于加速比。

① Self-Attention 的张量级展开

投影

X 为 [B,S,d]。Q=XWq、K=XWk、V=XWv。普通 MHA 有相同的 head 数；GQA 让 h_kv < h_q，多个 query head 共享一组 K/V；MQA 进一步只有一组 K/V。

位置

RoPE 只旋转 Q/K 的成对维度，使点积带相对位置信息。它不是把位置向量简单相加；长上下文扩展还涉及频率缩放与训练分布。

因果注意力

$A = \mathrm{softmax}\!\left(\dfrac{QK^\top}{\sqrt{d_{\text{head}}}} + M\right)$，再算 $O = AV$，拼接各 head 后过 $W_o$。第 i 个 token 不能读取 i 之后的 token。

KV cache

自回归解码时保存每层已生成位置的 K/V，只为新 token 算 Q；缓存形状近似 [B,h_kv,S,d_head]，所以 GQA/MQA 能直接减少 KV 显存。

一个具体形状例子

假设 B=1,S=4096,d_model=4096,h_q=32,h_kv=8,d_head=128：Q 是 [1,32,4096,128]，K/V 是 [1,8,4096,128]；每 4 个 Q head 复用一个 KV head。注意力得分不是永远保存完整的 S×S 矩阵，FlashAttention 用分块 IO 计算以降低显存峰值。

用具体尺寸读一次

若 B=2、S=3、d_model=4、d_ff=8，输入是 2 个样本、每个 3 个 token、每个 token 4 个数。gate 和 up 两条 Linear 各把每个 4 维向量变成 8 维，所以两支均为 [2,3,8]；SiLU 与逐元素乘仍为 [2,3,8]；down 再将每个 8 维向量映射为 4 维，得到 [2,3,4]，最后才能和形状相同的残差输入逐元素相加。

这个 MLP 放在什么位置？每个 decoder block 通常先做 attention 并加回残差，再归一化，然后对每个 token 独立运行上面的 MLP，再做第二次残差相加。Attention 混合 token 之间的信息；MLP 在一个 token 内混合通道、增加非线性表达。模型代码里 gate_proj/up_proj/down_proj 是参数名，不是特殊数学算子。并非所有模型都用 SwiGLU；有的使用 GELU/GEGLU 或 fused kernel，必须按模型实现确认。MoE 则把一份 MLP 扩展成多个 expert，并由 router 为 token 选择少数专家。

2. rollout：让当前策略生成可评分轨迹

4. RLHF 的两种闭环

经典 RLHF / PPO

先做 SFT policy；再用 prompt + 多个回答训练 reward model；rollout 得到回答和 log-prob；RM 给 scalar reward；用 value head/GAE 算 advantage；PPO 以 clipped ratio 更新 policy，并加入 $\mathrm{KL}(\pi_\theta \,\|\, \pi_{\text{ref}})$ 惩罚。需要同时保存 policy、reference、RM、value、optimizer 和 rollout 版本，工程成本最高但可以在线探索。

离线偏好优化

DPO/IPO 直接使用 chosen/rejected 和 reference log-prob，不在训练中调用 RM，也不需要每轮 rollout。它更适合已有稳定偏好数据；如果奖励依赖工具执行、游戏得分或长链路状态，离线 pair 往往覆盖不足，应回到在线 RL 或混合方案。

5. 训练和验收的最小客制化方案

  1. 写规格：目标用户、任务分布、必须遵守的格式、允许使用的工具、拒答和隐私边界、离线指标阈值。
  2. 建数据：原始样本、清洗日志、来源/许可证、标注指南、train/validation/held-out/red-team 按用户或时间切分。
  3. 先做 SFT：用 50—500 条高质量样本验证模板和 target mask；对比基座、RAG、LoRA，记录 loss 之外的任务指标。
  4. 再做偏好：同一 prompt 生成 2—4 个候选，按 rubric 标 chosen/rejected；先跑 DPO，确认偏好收益后再考虑 RM。
  5. 最后做在线 RL：限定 rollout 数量和最大 KL；每轮保存 reward 分量、成功率、拒答率、长度、KL、checkpoint 和失败样本，发现奖励投机就暂停更新。
  6. 发布前验收：固定回归集、独立盲评、红队、工具沙箱、长上下文、旧能力和恢复训练；只在所有门槛通过后导出 adapter 或合并权重。

从 logits 到 LoRA 梯度

这里先用得到 LoRA，所以先把它的最小定义说清楚（完整挂载点与实操见 07 · LoRA 的真实挂载点）：LoRA 不改原来的权重 W，而是在它旁边并联两个小矩阵：$h = Wx + \frac{\alpha}{r} B A x$，其中 $A \in \mathbb{R}^{r \times k}$、$B \in \mathbb{R}^{d \times r}$，r 远小于 d、k（常见 4–64），$\alpha/r$ 是缩放系数。训练时冻结 W，只有 A、B 接收梯度与优化器状态；推理时可以把 $\Delta W = \frac{\alpha}{r}BA$ 加回 W，所以不增加推理延迟。这就是下面这段梯度路径要讲的「冻结了什么、什么还在算梯度」。

交叉熵对最后一层 logits 的梯度是 p - one_hot(y)。它沿 LM head、最后一层、所有被使用的 block 反向传播；当基座参数 requires_grad=False 时，autograd 仍需经过冻结层计算对输入的梯度，才能更新早先位置的 LoRA A/B。LoRA 只保存 A/B 的梯度和优化器状态，冻结 W 不等于 forward 不经过 W。

图像和视频的具体 LoRA 挂载会在本部按任务展开：图片先经 VAE 变为 latent，随机时间点加噪，文本变成条件，U-Net/DiT 预测 target；视频再增加 3D VAE、空间/时间 token 和帧间一致性。这里先记住梯度方向：LoRA 挂在 cross-attention 的 K/V 会改变条件读取，挂在 self-attention 会改变 token 关系，挂在 MLP 会改变通道表征；这只是功能假设，必须用不同 target_modules 做消融。

原始像素和波形都是「稠密」的：图像 3×1024×1024，视频 3×121×720×1280（5 秒 720p），音频 2×480000。[B,3,1024,1024] 在 fp16 下约 6.3 MB，压成 [B,4,128,128] latent 后只有约 0.13 MB，相差约 48 倍。视频这条更夸张：原始张量约 3.35 亿个数、fp16 下约 669 MB，压成 [B,24,31,45,80] 只剩约 268 万个数、约 5.4 MB，相差约 125 倍。

这个倍数可以自己拆开核对：视频 VAE 的每个 latent 位置对应 16×16 空间块 × 4 帧时间块，也就是 3×16×16×4 = 3072 个原始数值，被压成 24 个通道值，3072 / 24 = 128，与实测的约 125 倍一致（略小是因为 121 帧按 4× 压缩后是 31 而不是 30.25）。音频的账最简单：32000 / 40 = 800，比图像和视频都小得多，所以音频 latent 通常不是显存瓶颈。

三个最常见的坑：

  1. 维度顺序：NHWC 与 NCHW、[B,T,C,H,W] 与 [B,C,T,H,W]、[B,2,S] 与 [B,S,2] 都不是同一个张量。三次转置看起来无害，但放错位置不会报错，只会让模型学到垃圾。
  2. 值域与 dtype：0–255 的 uint8 直接进卷积会得到完全不同的激活；冻结的 VAE 和文本/图像编码器各自要求固定的归一化（扩散主干用 [−1,1]，CLIP 图像塔用 CLIP 自己的 mean/std，不能随便换）。fp16 还要留出数值范围，避免在 ×2−1 之后再乘大系数导致溢出。
  3. 长度对齐：T = fps × 秒数 + 1 的 ±1 要写清；VAE 的时间压缩倍数（4× / 8×）通常要求 T 能被整除，靠 padding 或裁尾解决；音频 40 Hz latent 与视频 24 fps 又是两条不同的时间率，必须映射到同一参考系——这就是「原生音画同步」要解决的问题。

1. 从像素到 latent：为什么生成器不直接处理 RGB

像素图通常写成 $x \in \mathbb{R}^{B\times 3\times H\times W}$：B 是图片批次，3 是 RGB 通道，H/W 是高宽。VAE（Variational Autoencoder，变分自编码器）由 encoder 和 decoder 组成：encoder 把像素压成较小的 latent $z \in \mathbb{R}^{B\times C\times H'\times W'}$，生成主干在 z 上加噪和预测，最后 decoder 把干净 latent 还原为 RGB。$H' = H/f$、$W' = W/f$，f 是空间压缩因子；它不是“把图片裁剪掉”，而是用通道特征保存压缩后的视觉信息。

2. Patch、token 与 patchify：把二维网格变成序列

3. 上下采样与压缩率：只改形状，不改条件

4. 扩散模型到底是什么：前向加噪与反向去噪

一句话：训练时人为往干净 latent 上加噪，推理时从纯噪声出发，把同一个网络迭代调用很多次，一步一步把噪声减回去。网络在任何一步只学“给定当前带噪 latent z_t、时间 t 和条件 c，这一步里有多少噪声、该往哪个方向走”，它从来不是“输入 prompt 直接输出图片”的一步映射。一次生成要几十次前向，正是因为整条去噪轨迹被切成几十小步，每一步都由网络重新估计一次，而真正出图的最后一步也不是网络直接给的，而是 scheduler 按公式从当前 z_t 和网络预测算出来的。

前向过程（forward process）是固定的、没有可学参数的：它规定噪声怎么逐步加到数据上。逐步写法是每一步只加一点点高斯噪声，得到 $q(z_t \mid z_{t-1}) = \mathcal{N}\!\left(\sqrt{1-\beta_t}\,z_{t-1},\ \beta_t I\right)$

其中 β_t 是第 t 步注入的噪声方差，α_t = 1 − β_t 是这一步保留的信号比例，而累积量 $\bar\alpha_t$ 是从第 1 步乘到第 t 步的结果： $\alpha_t = 1-\beta_t$、$\bar\alpha_t = \prod_{s=1}^{t}\alpha_s$。β_t 随 t 增大（后几步加得更多），所以 $\bar\alpha_t$ 是随 t 单调下降的曲线：t 很小时接近 1，t 接近 T 时接近 0。这条曲线就是后文反复出现的“调度”。

因为每步都是高斯，而高斯串联后仍是高斯，前向过程有闭式解：不必真的循环 t 次，也能直接写出第 t 步的分布 $q(z_t \mid z_0) = \mathcal{N}\!\left(\sqrt{\bar\alpha_t}\,z_0,\ (1-\bar\alpha_t)I\right)$

把它写成可直接采样的形式，就是全篇最有用的一条式子： $z_t = \sqrt{\bar\alpha_t}\,z_0 + \sqrt{1-\bar\alpha_t}\,\epsilon,\ \epsilon \sim \mathcal{N}(0,I)$。这条式子的含义是：“加噪 t 步”等价于一次乘法加一次加法。训练时随机抽一个时间点 t，用同一个 z_0、同一个 ε 一次性算出 z_t 即可，不需要真的迭代 t 次；这正是扩散模型能在随机时间点上做单步训练、而不是跑整条链的原因。这里的 z_0 通常不是像素，而是图像过 VAE 编码器得到的干净 latent，加噪发生在 latent 空间；解码回像素只发生在整条去噪链结束之后。

记号 含义 取值 / 典型值
z_0 干净 latent，VAE 编码器输出，也是 x_0-prediction 的目标 形状 [B,C,h,w]，值域约 [−1,1]
ε 人为采样的标准高斯噪声，训练时唯一随机的输入 $\epsilon \sim \mathcal{N}(0,I)$
β_t 第 t 步的噪声方差，由 beta schedule 生成 约 1e−4 到 2e−2，随 t 增大
α_t 单步信号保留系数，$\alpha_t = 1-\beta_t$ 接近 1（如 0.999）
$\bar\alpha_t$ 累积信号保留系数，训练调度的全部信息都在这一条曲线上 t 小 → 约 1；t 大 → 约 0
z_t 第 t 步的带噪 latent，也是主干每一步的唯一视觉输入 与 z_0 同形状
σ_t 常用简写：这一步的噪声系数 $\sqrt{1-\bar\alpha_t}$ t 小 → 约 0；t 大 → 约 1
T 训练用的离散总步数，决定 β 表长度 常见 1000

反向过程（reverse process）是把上面这条链倒着走。它写作 $p_\theta(z_{t-1} \mid z_t)$，是一个条件高斯，但它的真实均值没有闭式解，只能让网络去逼近。推理时的循环是：从 $z_T \sim \mathcal{N}(0,I)$ 出发，每一步把当前 z_t、时间 t 和条件 c 送进主干，拿到预测，由 scheduler 算出 z_{t−1}，重复到 t=0 得到 z_0，最后交 VAE 解码器变成像素。

网络输出和“往前推一步”的关系，在 ε-参数化下可以写全。网络预测 $\epsilon_\theta$ 之后，这一步的目标均值由它和当前 z_t 直接换算： $\mu_\theta(z_t,t) = \dfrac{1}{\sqrt{\alpha_t}}\left(z_t - \dfrac{\beta_t}{\sqrt{1-\bar\alpha_t}}\,\epsilon_\theta(z_t,t,c)\right)$

然后按这个均值加回一点随机性，得到下一步：$z_{t-1} = \mu_\theta(z_t,t) + \sigma_t\,\xi,\ \xi \sim \mathcal{N}(0,I)$；最后一步（t=1）通常不再加噪声，直接取均值。三个量的分工因此非常清楚：$\epsilon_\theta$ 是网络唯一真正输出的东西（一个和 z_t 同形状的张量）；$\mu_\theta$ 不是网络输出，而是 scheduler 用 $\epsilon_\theta$ 和 z_t 按上式算出来的这一小步的落脚点；σ_t 是这一步还剩多少随机性，DDPM 常取反向方差 $\tilde\beta_t = \dfrac{1-\bar\alpha_{t-1}}{1-\bar\alpha_t}\,\beta_t$（也可简化为 β_t），DDIM 一类确定性采样器则直接取 σ_t = 0。换句话说，同一份 $\epsilon_\theta$，配不同的 μ、σ 公式，就是不同的 sampler。

时间步是离散的：训练时 t 从 $\{1,\dots,T\}$ 里采样，常见做法是均匀采样，也有按噪声水平加权（例如偏向中间段的对数正态或 logit-normal 采样）；T 常见 1000。推理时只用 K = 20–50 步，这个 K 不等于 T，也不是“把时间重新编号成 1 到 K”：scheduler 会从 0…T−1 这份训练时间表里挑出 K 个点放进 timesteps 数组，主干只在这 K 个点上被调用。把 1000 和 50 当成一回事，是“权重里明明写着 1000 步，为什么别人 20 步就出图”这类困惑的根源；两者分别是训练时间表的长度和推理被调用次数。

流匹配（flow matching / rectified flow）：同一件事的另一种参数化

流匹配把“加噪”换成“在干净样本和噪声之间走一条直线”。定义 $z_t = (1-t)\,z_0 + t\,\epsilon$，其中 $t \in [0,1]$：t=0 是干净 latent，t=1 是纯噪声，中间是线性插值。对 t 求导立刻得到这一步的“速度” $v = \dfrac{dz_t}{dt} = \epsilon - z_0$。于是主干的目标从“预测噪声”变成“预测速度场 v”，推理就是把常微分方程沿 t 从 1 积到 0。最朴素的积分器是欧拉法，一步就是 $z \leftarrow z + \Delta t \cdot v_\theta(z,t)$

其中 Δt 是这一步的负步长（从 t=1 往 t=0 走，Δt < 0）。注意这里没有“另外加回随机噪声”这一项，所以流匹配采样天然是确定性的，随机性只来自起点 z_1 的采样。它和 DDPM 不是两套数学，而是同一件事的两种参数化：DDPM 的 $\bar\alpha_t$ 与 σ 满足 $\bar\alpha_t$ + (1−$\bar\alpha_t$) = 1，走的是 (α, σ) 平面上的一条四分之一圆；流匹配走的是同一条平面上的直线（所以叫 rectified）。用 log-SNR $\lambda_t = \log\dfrac{\bar\alpha_t}{1-\bar\alpha_t}$ 看，两者都是“信号系数随噪声水平下降”的同一条曲线，只是把预测目标分别写成了噪声、干净样本或曲线切线方向；所谓 v-prediction 与 flow velocity 就是同一个切线方向在这两条路径上的两种写法。

具体数字：T = 1000、$\bar\alpha_t$ 从约 1 衰减到约 0 到底是什么样

取 SD 1.5 / SDXL 常用的 scaled_linear 调度（β 从 0.00085 到 0.012 共 1000 步），可以算出 $\bar\alpha_t$、信号系数 $\sqrt{\bar\alpha_t}$、噪声系数 $\sqrt{1-\bar\alpha_t}$：

t=1 时 $\bar\alpha_t \approx 0.9992$，信号系数 0.9996、噪声系数 0.029 → z_t 几乎是原图；t=250 时 $\bar\alpha_t \approx 0.675$，信号 0.822 对噪声 0.570；t=500 时 $\bar\alpha_t \approx 0.278$，信号 0.527 已被噪声 0.850 压过（SNR≈0.38）；t=750 时 $\bar\alpha_t \approx 0.057$，信号 0.238 对噪声 0.971；t=1000 时 $\bar\alpha_t \approx 0.0047$，信号系数只剩 0.068、噪声系数 0.998，z_t 已经接近纯噪声。

这组数字解释了训练时的直觉：小 t 的样本几乎就是原图，网络要学的是“几乎看不见的那层噪声”；大 t 的样本几乎是纯噪声，网络要学的是“从一片雪花里看回大致轮廓”。而 20 步推理等于把这条 1000 点的曲线只用 20 个采样点走完，每个点上的噪声水平由 scheduler 的 sigma 表给出——这也正是第 5 节要讲的“推理侧时间表”。

5. 训练目标：ε、v、x₀ 与 velocity

不管参数化怎么换，训练目标都是同一个形状：让网络在随机时间点上的预测去逼近一个由 z_0 和 ε 构造出来的 target，用均方误差回传梯度。 $L = \mathbb{E}_{z_0,\epsilon,t}\left[\,w(t)\,\lVert f_\theta(z_t,t,c) - \text{target} \rVert^2\,\right]$。其中 $f_\theta$ 是主干（U-Net / DiT），c 是条件（文本 embedding，以及参考图、mask 之类的额外条件），t 是随机采到的时间点，$w(t)$ 是时间权重。最常见的取法是 $w(t)=1$，也就是每个噪声水平的样本等权；也有按噪声水平加权的做法，例如 Min-SNR 权重 $w(t)=\min(\text{SNR}(t),\ \gamma)$（γ 常取 5 左右），它的动机是：纯 ε-预测的损失在高噪声端（$\bar\alpha_t$ 很小）损失数值很小但梯度方向很噪，低噪声端损失数值很大，加权后两端的有效梯度更接近平衡。微调脚本里如果出现 “min_snr_gamma”，说的就是这个 w(t)。

参数化 target（网络直接回归的东西） 定义式 典型使用者
ε-prediction 这一步加进去的噪声 ε target = ε SD 1.5、SD 2.0-base、SDXL 主流权重
x_0-prediction（clean） 干净 latent z_0 target = z_0 部分编辑 / 超分类管线，以及一些把干净 latent 当主输出的实现
v-prediction 信号与噪声的混合速度 v $v = \sqrt{\bar\alpha_t}\,\epsilon - \sqrt{1-\bar\alpha_t}\,z_0$ SD 2.1-768 一类权重（prediction_type: v_prediction）
velocity（flow matching） 直线路径的切线方向 $v = \epsilon - z_0$，路径为 $z_t=(1-t)z_0+t\epsilon$ SD3 / SD3.5、FLUX、Qwen-Image、Wan 等 flow 主干

v 的定义有两种整体差一个符号的写法：上面用的是 $v = \sqrt{\bar\alpha_t}\,\epsilon - \sqrt{1-\bar\alpha_t}\,z_0$，也有实现写成 $\sqrt{1-\bar\alpha_t}\,z_0 - \sqrt{\bar\alpha_t}\,\epsilon$。train 与 inference 只要在同一个代码库里自洽就不会错，但把别人的公式抄进自己的 sampler 时，很容易出现“每步方向反了”的情况；所以判断符号不要靠记忆，看代码里的 target 构造和 step 里用的是 +v 还是 −v。流匹配侧的符号也有同样问题：有的实现让 t=1 表示纯噪声，有的反过来让 t=0 表示纯噪声，此时 $v = z_0 - \epsilon$ 才是对的。

四种参数化之间可以随时互相换算，只要有 z_t 和其中任意一个预测量。记 $a=\sqrt{\bar\alpha_t}$、$b=\sqrt{1-\bar\alpha_t}$（即 a² + b² = 1）：

已知 求 $\hat\epsilon$（噪声） 求 $\hat z_0$（干净 latent） 求 $\hat v$（速度）
ε-prediction：$\hat\epsilon = f_\theta$ — $\hat z_0 = \dfrac{z_t - \sqrt{1-\bar\alpha_t}\,\hat\epsilon}{\sqrt{\bar\alpha_t}}$ $\hat v = \dfrac{\hat\epsilon - \sqrt{1-\bar\alpha_t}\,z_t}{\sqrt{\bar\alpha_t}}$
x_0-prediction：$\hat z_0 = f_\theta$ $\hat\epsilon = \dfrac{z_t - \sqrt{\bar\alpha_t}\,\hat z_0}{\sqrt{1-\bar\alpha_t}}$ — $\hat v = \dfrac{\sqrt{\bar\alpha_t}\,z_t - \hat z_0}{\sqrt{1-\bar\alpha_t}}$
v-prediction：$\hat v = f_\theta$ $\hat\epsilon = \sqrt{1-\bar\alpha_t}\,z_t + \sqrt{\bar\alpha_t}\,\hat v$ $\hat z_0 = \sqrt{\bar\alpha_t}\,z_t - \sqrt{1-\bar\alpha_t}\,\hat v$ —
flow velocity：$\hat v = f_\theta$（$t\in[0,1]$） $\hat\epsilon = z_t + (1-t)\,\hat v$ $\hat z_0 = z_t - t\,\hat v$ —

用公式时记住两条边界：第一，除以 $\sqrt{\bar\alpha_t}$ 或除以 $\sqrt{1-\bar\alpha_t}$ 在两端都会放大误差，所以换算出来的 $\hat z_0$ 在高噪声端会很不可靠（这也是 sampler 在高噪声端只走一小步的原因）；第二，$\hat z_0$ 换算出来可能超出 [−1,1]，是否 clamp 到合法值域取决于实现，不要想当然。

为什么还要有 v-prediction？把三种参数化的误差放大关系写出来就清楚了。记 $e_\epsilon$ = $\hat\epsilon$ − ε、e_0 = $\hat z_0$ − z_0，由 z_t = a z_0 + b ε 可以直接推出 e_0 = −(b/a) $e_\epsilon$ = −$e_\epsilon$ / √SNR，以及反过来 $e_\epsilon$ = −(a/b) e_0。也就是说：ε-prediction 的 ε 误差在还原成干净 latent 时被 $\sigma_t/\sqrt{\bar\alpha_t}$ 放大，噪声越大放大越狠；x_0-prediction 的 z_0 误差在还原成 $\hat\epsilon$ 时被 $\sqrt{\bar\alpha_t}/\sigma_t$ 放大，噪声越小放大越狠。两端各自崩一边。而 v 是一个把两者混在一起的量，误差在两端的放大系数都小于 1：$e_0 = -\sigma_t\,e_v$、$e_\epsilon = \sqrt{\bar\alpha_t}\,e_v$（flow 侧同理，$e_0 = -t\,e_v$、$e_\epsilon = (1-t)\,e_v$）。

具体数字：同一个 0.1 的预测误差，在不同参数化下变成多大的 latent 误差

仍用 scaled_linear、T=1000。在 t=900（$\bar\alpha_t \approx 0.0143$、a≈0.120、b≈0.993）处，取 $\hat\epsilon$ 的误差为 0.1：ε-prediction 把它还原成 $\hat z_0$ 时放大 $b/a \approx 8.3$ 倍，干净 latent 上就是 0.83 的误差；换成 v-prediction，同样 0.1 的 $\hat v$ 误差只对应 $b \approx 0.993$ 倍的 z_0 误差，约 0.099。反过来在 t=100（$\bar\alpha_t \approx 0.895$、a≈0.946、b≈0.323）处，x_0-prediction 的 0.1 误差会被 $a/b \approx 2.9$ 倍放大成 0.29 的噪声误差，而 v-prediction 只放大 $a \approx 0.946$ 倍。

所以 v-prediction 的优势不是“更准”，而是误差在高噪声端和低噪声端都保持同一量级；少步采样（起点就是高噪声）和蒸馏（要一步跨很远）最怕的正是高噪声端误差爆掉，这就是 v 在少步与蒸馏场景里常见的原因。

实际模型用哪种参数化，可以直接从权重名判断，不需要猜：SD 1.5、SD 2.0-base、SDXL 主流权重是 epsilon；SD 2.1-768 是 v_prediction；SD3 / SD3.5、FLUX、Qwen-Image、Wan 这类 flow 主干用的是 velocity（它们的 scheduler 是 FlowMatchEulerDiscreteScheduler 一类，config 里没有 prediction_type，因为 flow 侧参数化基本固定为速度）。

prediction_type 必须和 sampler 匹配：sampler 拿到的永远是网络输出的那个张量，它按 config 里声明的参数化去解释。声明成 ε 而权重实际在预测 v，每一步的方向和幅度都不对，结果是画面糊成一团、过曝、或者几十步下来噪声根本没被减掉；反过来同理。权威来源只有一个——checkpoint 的 scheduler_config.prediction_type（Diffusers 里就是 pipe.scheduler.config.prediction_type），换 sampler、换 LoRA、换 pipeline 都要以它为准，而不是以模型名或别人的工作流截图为准。上游文件缺失时，用 model_index.json 找到 scheduler 目录，再读它的 scheduler_config.json。

最后一条实践纪律：微调时沿用基座的目标与参数化，不要自己换。基座是 ε-预测就继续用 ε-预测做 loss，基座是 flow velocity 就继续回归 ε − z_0。换 target 等于让权重去学一个它从未被训练过的映射，LoRA 那点容量补不回来，而且微调出来的权重会和基座的推理链路不匹配。同理，训练脚本里的 target 构造、噪声调度、时间采样方式都应先和基座对齐，再谈改哪里。

6. 噪声调度与 sigma 表：每一步的噪声水平从哪来

噪声调度的本质是一条曲线：$\bar\alpha_t$ 随 t 怎么从 1 掉到 0。把它换成更直观的信噪比，就是 $\text{SNR}(t) = \dfrac{\bar\alpha_t}{1-\bar\alpha_t}$。SNR 从 t 小时的很大（几千）降到 t 大时的接近 0。用对数形式 $\lambda_t = \log \text{SNR}(t)$ 看，整条调度就是一条从左上到右下的单调曲线：“哪一段更陡”决定了训练和推理把步数花在哪里——陡的段落每走一步噪声水平变化大，缓的段落走一步变化小。所谓“换调度”，换的就是这条曲线的形状，而不是换网络。

beta schedule 写法 / 公式 曲线特征 谁在用
linear β_t 从 β_start 到 β_end 等间隔，常见 0.0001 → 0.02 尾部掉得太快：t 过 700 以后 $\bar\alpha_t$ 已经接近 0，最后两三百步几乎全是纯噪声，贡献的有效去噪步很少 最早期的 DDPM 实现
scaled_linear 在 √β 上等间隔：$\beta_t = \left(\text{linspace}(\sqrt{\beta_{\text{start}}},\sqrt{\beta_{\text{end}}},T)\right)^2$，常见 0.00085 → 0.012 起点更小、整体更平缓；$\bar\alpha_t$ 在中间段下降快，两端慢，步数分布比 linear 均匀 SD 1.5、SD 2.x、SDXL（beta_schedule: "scaled_linear"）
cosine $\bar\alpha_t = \dfrac{f(t)}{f(0)}$，$f(t)=\cos^2\!\left(\dfrac{t/T+s}{1+s}\cdot\dfrac{\pi}{2}\right)$，s 常取 0.008 两端变化慢、中间变化快，避免 linear 尾部“信息瞬间归零”；由 β_t = 1 − $\bar\alpha_t$/$\bar\alpha_{t-1}$ 反推时通常 clip 到 0.999 改进型 DDPM、不少研究实现（Diffusers 里叫 squaredcos_cap_v2）
sigmoid 在 log-SNR 上用一条 sigmoid 曲线分配噪声水平 中间段被拉平，信息量在两端分布更均匀，配合少步采样器时步长分配更稳 部分研究实现与视频 / 音频主干

cosine 与 sigmoid 的动机相同：linear 调度在 t 很大时 β 累积得太快，$\bar\alpha_t$ 早早归零，于是大量训练步浪费在“已经全是噪声、几乎学不到东西”的区域；把曲线改成两端慢中间快，等于把同样的 T 步更均匀地铺在 SNR 轴上。反过来，训练时如果按噪声水平加权采样 t（logit-normal 之类），效果和改调度曲线类似：都是把有效样本挪到中间段。

到了推理侧，决定每一步噪声水平的东西不再是 β_t，而是 scheduler 里那份sigma 表 / timesteps 数组。它的任务是把训练用的 T 步压缩成推理用的 K 步（20–50），并给出这 K 个点的具体噪声水平。控制这份数组的常见字段是 timestep_spacing：

spacing 怎么取点 直观效果
leading 从 t=0 这一头按固定间隔往上取 K 个点（间隔约 T/K），最高点落在 T−T/K 附近，不到 T−1 起点噪声略低于训练最噪的那几档，收尾干净；少步时会显得“图偏灰、对比度弱”
trailing 从 t=T−1 这一头按固定间隔往下取 K 个点，第一步正好是最大噪声，最后一格落在 T/K 附近再收到 0 起点噪声给足，构图先定下来；SDXL 一类 pipeline 常把它作为默认，步数少时比 leading 更稳
linspace 在 0…T−1 上直接等分，头尾都落在端点上 最“平均”的取法，步数很少时会牺牲高噪声端的精度
use_karras_sigmas 不用等间隔，而是让 sigma 沿一条幂曲线 $\sigma_i = \left(\sigma_{\max}^{1/\rho} + \dfrac{i}{K-1}\left(\sigma_{\min}^{1/\rho}-\sigma_{\max}^{1/\rho}\right)\right)^{\rho}$（ρ 常取 7）分布 Karras 曲线：大 sigma 段用少数几步跨过去，把大部分步数花在低噪声端；细节是在低噪声区被定下来的，所以它特别适合 Euler / DPM-Solver 这类低噪声端敏感的解算器
timestep_type 在“连续 sigma”和“离散 timestep”之间切换（有的实现叫 use_flow_sigmas / timestep_type: "continuous"） 只影响是否把时间取整；取整会改变每一步的实际噪声水平，复现别人的图时这也会造成差异

flow matching 侧的表更简单：常见约定就是 $\sigma = t$，sigma 从 1 线性走到 0，再按 shift 做一次重排 $\sigma' = \dfrac{\text{shift}\cdot\sigma}{1+(\text{shift}-1)\sigma}$

这个映射把 σ 整体往上抬：shift > 1 时，同一个 σ 被映射到更大的值，于是分给高噪声区间的步数变多、分给极低噪声端的步数变少。以 K=20、shift=3 为例，重排后 σ > 0.5 的点有 16 个（不 shift 时正好 10 个），而 σ < 0.2 的点只剩 1 个（不 shift 时 3 个）。这和“高分辨率需要更大 shift”的经验是一致的：像素越多，同样大小的 σ 对画面的实际破坏越弱（噪声在更多像素上被平均掉），所以要把更多步留在高噪声区，先把整体构图和大色块定下来，再用少数几步收拾细节。FLUX、Qwen-Image 这类主干会把 shift 设成动态值：由 latent 序列长度算出 mu（序列越长 shift 越大），因此同一条 pipeline 在 512² 和 2048² 上自动用不同的时间表；视频侧因为帧数多、序列更长，shift 通常还要再调大一些。

这张表里的数字都是该模型常见工作流里的起点，不是“官方唯一值”。决定实际行为的始终是 checkpoint 自带的那份配置：scheduler_config.json 里的 num_train_timesteps（T 到底是多少）、beta_schedule（曲线形状）、prediction_type（参数化），加上推理时由 pipeline 默认参数决定的 timestep_spacing、use_karras_sigmas、shift。同一份权重配不同的推理时间表，出图质量和风格就会变，所以“这个模型应该跑几步”永远应该先去读它的 pipeline 默认值，而不是背一个数字。

具体数字：20 步时 Karras 表与等间隔表差别有多大

仍以 K=20、σ 从 80 降到 0.002 的传统扩散约定为例。等间隔取点时，σ < 1 的点只有 1 个——也就是说 20 步里有 19 步都花在“噪声极大、只能定大色块”的区域，真正决定细节的低噪声段只有一步。换成 Karras 曲线（ρ=7）后，σ < 1 的点变成 9 个，接近一半的步数落在低噪声端。

反过来，flow 侧的 shift 做的正好是相反方向的事：shift 从 1 调到 3，σ > 0.5 的步数从 10 个变成 16 个。两类时间表不是谁更“对”，而是把有限步数分给哪一端的取舍：Karras 认为细节值钱，shift 认为高分辨率下的大结构更值钱。理解了这一点，就能判断别人的工作流为什么在某个 sampler 上写死了一个奇怪的 sigma 配置。

7. sampler、scheduler 与 solver：谁在每一步做什么

这三个词在文档和代码里经常混用，先把它们拆开：

词 指什么 决定什么 出现在哪
noise scheduler（训练侧） 加噪曲线本身：β_t、α_t、$\bar\alpha_t$ 和 sigma 表 每个时间点的噪声水平；训练时怎么造 z_t 训练脚本、checkpoint 的 scheduler_config
sampler / solver（推理侧） 从 z_t 推到 z_{t−1} 的那条数值更新公式（DDIM、Euler、DPM-Solver++、Heun…） 每一步走多远、走几步、要不要注入随机噪声 推理 pipeline 的 sampler 名字、ComfyUI 的采样器下拉框
Diffusers 的 SchedulerMixin 对象 一个类同时装了 sigma 表和更新公式，既是训练侧的表，也是推理侧的 solver 上面两件事都由它提供，所以文档里常把 scheduler 和 sampler 当同义词 pipe.scheduler、DDIMScheduler、EulerDiscreteScheduler、FlowMatchEulerDiscreteScheduler

读代码时这样区分最省事：看它是被 set_timesteps() 产生时间表，还是被 step() 用来推下一步。前者是“表”，后者是“解算器”；Diffusers 里两者在同一个对象上，所以 scheduler.step(model_output, t, z_t) 会同时用到表和解算器。下面统一用 Karras / EDM 的 σ 约定写更新式：在那里 $z_t = z_0 + \sigma_t\,\epsilon$，σ 从大到小走到 0；它和 DDPM 的 $\bar\alpha_t$ 可以互换，$\sigma_t = \sqrt{(1-\bar\alpha_t)/\bar\alpha_t}$，而 $\hat z_0$ 与 $\hat\epsilon$ 的换算关系不变。

DDIM（确定性，η = 0）。它先用模型输出算出 $\hat z_0$ 和 $\hat\epsilon$，再直接跳到目标噪声水平： $z_{t-1} = \sqrt{\bar\alpha_{t-1}}\,\hat z_0 + \sqrt{1-\bar\alpha_{t-1}}\,\hat\epsilon$。这条式子没有任何随机项，所以同一组 seed 和 prompt 下结果可复现。要注入随机性就把系数写成 $\eta$ 控制的形式：方差取 $\sigma_t^2 = \eta^2\,\dfrac{1-\bar\alpha_{t-1}}{1-\bar\alpha_t}\left(1-\dfrac{\bar\alpha_t}{\bar\alpha_{t-1}}\right)$，$\hat\epsilon$ 的系数相应变成 $\sqrt{1-\bar\alpha_{t-1}-\sigma_t^2}$，再额外加一项 $\sigma_t\xi$；η=1 就退化成 DDPM 采样。DDIM 更重要的性质是可以跳步：更新式里的 t−1 可以是任意更小的 t′，不必是相邻整数，这正是“少步推理”的起点，也是 20 步 DDIM 能出图、而 20 步原始 DDPM 不行（DDPM 的 β 是训练出来的逐步方差）的原因。

Euler / Euler ancestral。欧拉法把去噪看成解 ODE，一步沿 σ 方向线性外推： $z_{t-1} = z_t + (\sigma_{t-1} - \sigma_t)\,\dfrac{dz}{d\sigma}\right|_{\sigma_t}$

其中导数由模型预测直接给出：$\dfrac{dz}{d\sigma} = \dfrac{z_t - \hat z_0}{\sigma_t}$（等价地等于 $\hat\epsilon$，因为在 $z = z_0 + \sigma\epsilon$ 的约定下 $dz/d\sigma = \epsilon$）。也就是说 Euler 一步做的事情是“把当前点朝模型认为的干净点方向直线走一步”，步长就是 σ 的差值。ancestral 版本在每步之后额外把噪声加回去（把 σ 抬到 $\sigma_{\text{up}} > \sigma_{t-1}$ 再重新降下来），所以结果是随机的、每次都不一样；步数少时它额外注入的噪声占比大，画面会显得更“脏”但也更“活”，这是 Euler a 与 Euler 观感不同的根源。

Heun / 二阶方法。先用欧拉走半步拿到一个临时点，在那个点上再预测一次，然后用两处导数的平均做一次修正：$z_{t-1} = z_t + \dfrac{\sigma_{t-1}-\sigma_t}{2}\left(\dfrac{dz}{d\sigma}\right|_{\sigma_t} + \dfrac{dz}{d\sigma}\right|_{\sigma_{t-1}}\right)$。一阶方法的局部误差是 O(Δσ²)，二阶是 O(Δσ³)，所以同样步数下二阶更准、对步长更不敏感；代价是每一步要两次前向，时间与显存大致翻倍。步数给得足（30 步以上）时两者差距很小，步数压到 15 步以下时二阶通常明显更稳、更少出现结构错位。

DPM-Solver++(2M)。它先把扩散 ODE 换到 $\lambda = \log(\bar\alpha_t/(1-\bar\alpha_t))$ 这个变量下，使得解可以用一个关于 λ 的指数积分近似，再把 $\hat z_0$ 当成被积函数做多步二阶外推（2M 指二阶、multi-step，用上一步的 $\hat z_0$ 一起拟合）。它的两个实际好处是：只依赖 $\hat z_0$，因此天然兼容 ε / v / flow 各种参数化（只要按第 4 节的换算表先把 $\hat z_0$ 算出来），以及误差在噪声水平轴上分布得更均匀，所以 15–25 步就能出接近 50 步 DDIM 的结果，成了目前最常用的默认解算器之一。

UniPC 与一致性类（LCM / 一致性模型 / 蒸馏 sampler）。UniPC 是“统一预测—校正”框架：每一步先用多阶外推预测一个点，再用低阶公式校正一次，本质上是把 DPM-Solver 系列和预测校正思想统一起来，属于同类低步数解算器。LCM、一致性模型、以及各种 turbo / lightning 权重则不是更好的积分器，而是把多步过程蒸馏成极少步映射：它们训练网络让 $f_\theta(z_t,t)$ 在少数几个噪声水平上直接落到对应的 z_0 或相邻轨迹点上。因此这类权重只能用配套的 sampler 和很少的步数（1–8 步），硬套 30 步 DDIM 反而会糊。

flow 的 Euler（FlowMatchEulerDiscreteScheduler）。更新式和上面的欧拉法完全是同一个欧拉积分，只是参数化换成了速度： $z \leftarrow z + (\sigma_{\text{next}} - \sigma)\cdot v_\theta(z,\sigma)$

其中 σ 由 sigma 表给出、σ_next 是下一个更小的噪声水平，v_θ 是速度预测。因为 flow 路径是直线、速度场在整个区间上变化平缓，同样步数下它的离散化误差通常比 VP 扩散更小，这也是 flow 主干敢用 20 步左右的原因；反过来，如果拿 DDPM 侧的 DDIMScheduler 去驱动一个 flow 权重（或反过来），因为参数化和 σ 含义都不一致，结果会直接错掉。

为什么同一份权重换个 sampler 结果就变？三个原因：离散步长（同样 20 步，谁走的路更贴近真实 ODE 解不一样）、随机性（ancestral 与 SDE 类采样器每步注入噪声，等价于在解上叠加了不同的扰动，最终落在不同的样本上）、二阶项（一阶方法扔掉的高阶信息被二阶方法捡回来，体现在细节和结构稳定性上）。所以“换 sampler”不是换滤镜，而是换了一条数值轨迹。

还有一条容易踩的坑：换 sampler 时，sigma 表要一起换。sampler 的更新式默认自己给出的 σ 序列是自洽的，但时间表（步点位置、是否用 Karras、shift 取多少、连续还是离散）是由 scheduler 的 set_timesteps() 重新生成的。把 A 的 timesteps 数组直接喂给 B 的 step 公式，等于用错的噪声水平去解释模型输出；反过来，只在 config 里改 sampler 名字而沿用旧的 sigmas，同样会出问题。换 sampler 的正确做法是替换整个 scheduler 对象（保留 num_train_timesteps、beta_schedule、prediction_type 这些训练侧字段），再重新调用一次 set_timesteps()。

实用建议：先固定 sampler 与步数，再比较模型——否则两个模型之间的差异里混着采样器差异，结论没有意义。用 CFG 时步数与 guidance 要一起调：guidance 调高会同时放大预测误差，低步数配高 guidance 最容易出结构崩坏，此时应该是“加步数 + 略微降 guidance”，而不是只动一个。要复现别人的图，必须同时对齐 sampler、调度（Karras / shift / spacing）、steps、guidance、seed 五项，缺一项结果就会不同；分辨率、latent 尺寸也会改变 dynamic shift 算出来的 mu，所以分辨率也属于复现条件。

8. CFG / guidance：为什么要算两次前向

训练时条件 c 有概率被丢成空条件（classifier-free guidance 的字面意思就是“不带分类器的引导”），于是同一个网络同时会做有条件预测和无条件预测。推理时把两者按 guidance scale s 组合： $\hat\epsilon = \epsilon_\theta(z_t,t,\emptyset) + s\cdot\left(\epsilon_\theta(z_t,t,c) - \epsilon_\theta(z_t,t,\emptyset)\right)$。这里的 $\emptyset$ 是空条件（无条件预测），s 就是 guidance scale。s = 1 时括号里的差值被原样加上去，公式退化成 $\hat\epsilon = \epsilon_\theta(z_t,t,c)$，也就是不做 CFG；s = 0 则完全忽略提示词，只用无条件预测。s > 1 是在“有条件方向”上做外推，等于让模型比它本身更极端地朝提示词走。

这个组合形式对四种参数化完全一样，只是把被组合的量换掉：ε-预测组合 $\hat\epsilon$，v-预测组合 $\hat v$，flow velocity 组合 $\hat v$，x_0-预测则组合 $\hat z_0$。组合结果直接交给 sampler 的 step()，所以 CFG 是“在 scheduler 之前”发生的一步，它不改变时间表。同一批权重里，s 调整的是这一步的预测方向与幅度，而不是噪声水平。

CFG 为什么有效，可以用隐式分类器解释：对 $\log p(z_t \mid c)$ 求梯度，由贝叶斯公式可得 $\nabla_{z_t}\log p(z_t \mid c) = \nabla_{z_t}\log p(z_t) + \nabla_{z_t}\log p(c \mid z_t)$。而 $\epsilon_\theta(z_t,t,c)$ − $\epsilon_\theta(z_t,t,\emptyset)$ 正是 $\nabla_{z_t}\log p(c \mid z_t)$ 的一个成比例估计（带负号与 σ_t 系数）。把这项乘上 s 再加回无条件预测，等价于用一个没有显式训练过的分类器去引导采样轨迹：s 越大，轨迹越偏向“这个 z_t 看起来像符合 c 的样本”的方向。代价也很直接：每一步要跑两次前向（一次有条件、一次无条件），显存与时间大致翻倍（批处理翻倍或两次串行前向），这是 CFG 最实际的成本，也是 guidance-distilled 模型想省掉的东西。

把空条件换成一段具体文本，就是负面提示词（negative prompt）：$\epsilon_\theta(z_t,t,c_{\text{neg}})$ 取代 $\epsilon_\theta(z_t,t,\emptyset)$，方向变成“远离负面描述”。它的效果强弱同样被 s 缩放，所以负面词写得又长又杂时，往往应该同时把 s 降一点，否则等于同时外推两个方向。

高 s 常带来另一个问题：过曝与色偏。原因是外推把预测的方差一起放大了，采样轨迹被推离了训练分布。修正手段是 CFG rescale——按标准差把组合后的预测重新标定回有条件预测的量级： $\hat\epsilon' = \hat\epsilon \cdot \dfrac{\mathrm{std}\left(\epsilon_\theta(z_t,t,c)\right)}{\mathrm{std}\left(\hat\epsilon\right)}$。实际实现里不会直接用 $\hat\epsilon'$ 替换，而是用一个 0–1 的 rescale 系数在两者之间混合（Diffusers 的 guidance_rescale，社区常取 0.7 左右），这样既能压住过曝，又不会把构图自由度过分收紧。

现在很多权重把引导直接训进了网络，成为 guidance-distilled / CFG-free：训练时把 guidance 值本身当作一个条件输入（例如 FLUX 的 guidance_embed，给时间条件的 MLP 多一路引导标量），推理时只需要一次前向，网络自己就知道“该按多强的引导画”。这带来两点和普通 CFG 不同的使用规则：第一，这类模型的 guidance 参数通常是固定值（发布方在训练时用过的那个值），而不是像 CFG 那样在 1–15 之间随便扫；第二，蒸馏权重的引导行为不等同于普通 CFG——它的引导是学出来的映射，继续往上调不会出现经典 CFG 那种“越调越锐、然后崩掉”的曲线，很多实现也不会再叠加一次真正的 CFG（true_cfg / 双引导），硬叠等于两套引导相加，结果容易失控。区分方法很简单：看 pipeline 里有没有 guidance 输入口（guidance_embed / guidance 参数）以及它是否需要 negative prompt。

这张表是社区常用起点，不是官方保证值：s 的最优值取决于模型版本、分辨率、步数、采样器和提示词本身，同一个权重在不同工作流里差 1–2 都很正常。

s 太高的典型症状：画面过饱和、对比度异常、肤色发红或发橙，构图僵硬（主体被硬塞到画面中央、姿态别扭），细节开始崩（手指、文字、小结构糊成一片），偶尔出现大面积噪点或色块；视频上还会表现为帧间闪烁与运动僵硬。s 太低的典型症状相反：画面“好看”但不跟随提示词——该有的物体缺失、属性串位（颜色、数量、材质错）、文字内容不对，负面提示词也基本不起作用。判断方法不是看单张图，而是固定 seed 只改 s，扫 3–4 个值比较提示词遵循与画面稳定性的平衡点。

最后把 s 和步数放在一起看：guidance 是在每一步对预测做外推，步数越少，每一步承担的变化越大，误差被放大的机会也越多；所以少步采样通常要用更温和的 guidance，而高 guidance 需要更多步去把轨迹拉回稳定区间。复现别人的结果时，guidance 必须和 sampler、调度、steps、seed 一起对齐——这五项才是同一条采样轨迹的完整描述。

9. 通用条件路径：文本、时间和参考图如何进入主干

文本 encoder 把 prompt 变成文本 token c_text；在 cross-attention 中，当前视觉 feature 产生 Q， c_text 经过投影产生 K/V，所以文本条件会在每一个 denoising step 的每个相关 block重新参与计算。 t 则经 time embedding 和小 MLP 变成 c_time，注入 ResNet/AdaLN 的 scale、shift 或 gate。参考图、mask、姿态或深度也要按模型实现，在每一步作为 latent、token 或 residual 条件进入；它们不是只在第一次输入后就永久留在网络里。

1. ViT block：图像版的 Transformer 块

ViT = Vision Transformer。它的核心思想只有一句：把图像当成一串 token，然后套用语言模型那套 Transformer 编码器。做法是把图切成固定大小的小方块（patch），每块展平后用一个线性层投影成向量，再加上位置编码，就得到 [B,N,D] 的序列——N 是 patch 数量，D 是模型宽度。之后每个 block 内部和语言模型完全一样：LayerNorm → 多头自注意力 → 残差 → LayerNorm → MLP → 残差。

ViT block 的完整结构（图像分类 / 视觉塔通用） 虚线框内是一个完整工程链路：图像 → patch embedding → + 位置编码 → L 个同构 block → 输出 token 序列（或一个全局向量）。
虚线框内＝一个完整结构

和语言模型 block 的唯一区别在两头：输入怎么来（patch embedding 而不是 tokenizer + embedding 表）、位置怎么给（可学习的绝对位置编码或 RoPE，而不是词表位置）。中间的 block 完全一样。所以看到「ViT block ×L」时，可以直接按上面这四步去读代码。

用在哪里：CLIP 的图像塔（SD 1.5 / SDXL / SD3 用它当图像条件，IP-Adapter 用的也是它）、Qwen2.5-VL 与 Qwen3-VL 的视觉塔（Qwen-Image 的文本编码器、H3-Encoder 都是这一路）、部分视频 VAE 的 ViT 解码器（H3 官方提到「编码器训练后另有 ViT 解码器」）。把 Conv2d 换成 Conv3d、patch 带时间维，就是视频 ViT；把注意力限制在局部窗口里，就是 窗口注意力（window attention），Qwen2.5-VL 的视觉塔就是窗口与全局注意力交替。

2. AdaLN：用条件去「调制」归一化

DiT（Diffusion Transformer）把 U-Net 换成 Transformer 之后遇到一个问题：卷积网络里时间步是「加到特征上」的，Transformer 里没有卷积，时间步往哪加？ 答案就是 AdaLN = Adaptive Layer Normalization（自适应层归一化）：不把条件加到特征上，而是用条件生成归一化的 scale（缩放）和 shift（平移），顺手再生成一个 gate（门控）去缩放残差分支。

AdaLN / AdaLN-Zero 的完整结构（一个 block 内） 虚线框内是一个完整 block：条件向量 → 6 组调制参数 → 两次归一化·调制·门控·残差。

AdaLN-Zero 多了什么：生成 gate 的那一层线性权重初始化为 0，于是训练刚开始时 gate = 0，整个 block 退化成恒等映射（输入直接穿过去）。这让非常深的 Transformer 也能稳定训起来。和 cross-attention 的分工：AdaLN 注入的是「一个全局条件向量」（时间步、pooled、类别、guidance），不携带位置；文本这种「一长串 token」走的是 cross-attention 的 K/V。两者不能互换。

用在哪里：DiT 原始论文（Peebles & Xie）、PixArt-α 系列、SD3 / SD3.5 的 MMDiT、FLUX、Qwen-Image，以及 MiniMax H3 的 H3-Omni 主干——H3 明确说「约 13B 参数在 AdaLN 分支」（该数字指官方 33B 原版权重；社区 int8 剪枝 repack 实测 AdaLN 相关约 43.65M，差异说明见 13.2），因为每个 block 都要一份调制参数，而且这些参数只依赖条件、可以预计算缓存，所以纯推理部署时不必加载。SD 1.5 / SDXL 的 U-Net 里没有 AdaLN，它们用的是 AdaGN：在 ResNet block 的 GroupNorm 之后用时间向量做 scale/shift，作用一样、位置不同。

3. MLP / FFN / SwiGLU / GEGLU：逐 token 的前馈网络

Transformer block 里 attention 之外的那一半。它对每个 token 单独做同一套线性变换，不混合不同位置的信息，作用是给模型非线性表达力（attention 负责「看别处」，MLP 负责「想一下」）。标准形态是「升维 → 激活 → 降维」，升维倍数通常 4×。

三种常见 FFN 形态 虚线框内是三条并列的完整前馈网络：普通两层 MLP、GELU 门控、SwiGLU 门控。它们形状相同、参数不同。

3D 版本只改两件事：卷积变成 CausalConv3d（时间维只看当前与过去帧）、归一化仍是 GroupNorm；时间维的下采样由 block 之后的 stride 卷积负责，不在这里。Up block 里为什么是 3 个 Resnet：因为要额外接住同尺度的 skip，Diffusers 用 layers_per_block + 1 个 Resnet 来消化拼接后的通道数。

用在哪里：SD 1.5 / SDXL 的 U-Net 每一级（Down / Mid / Up 全是它）、ControlNet、所有 AutoencoderKL 型 VAE 的编码器与解码器、H3 / Wan / CogVideoX 这类视频 VAE 的 ResBlock3D。

6. Transformer2DModel：U-Net 里的「空间 Transformer」

U-Net 是卷积网络，但它必须在 32×32、64×64 这些较低分辨率上做全局信息交换和文本条件注入，靠的就是插在 ResNet 之间的 Transformer2DModel（Diffusers 里也叫 Spatial Transformer）。它做的事情是：把特征图临时展开成 token 序列，做完注意力再折回特征图。

Transformer2DModel 的完整结构 虚线框内是一次完整 forward：特征图 → 展平成 token → self-attn → cross-attn（读文本 c_text）→ FFN → 折回特征图 → 残差。

7. 位置编码：模型怎么知道 token 在空间/时间上的位置

attention 本身是「无序」的：把 token 打乱顺序，输出只跟着打乱。所以必须显式注入位置信息。工程上常见四种做法，看代码时先确认是哪一种。

类型 怎么加 外推能力 用在哪
可学习绝对位置（learned absolute） 一张 [max_N,D] 的参数表，按序号取出来加到 token 上 差，换分辨率要插值 ViT / CLIP 图像塔、DiT 的 pos_embed（SD3 有 pos_embed_max_size=192）
正弦位置（sinusoidal） 用不同频率的 sin/cos 直接算出来，无参数 好 扩散模型的时间步编码（DDPM / SD / FLUX 的 time_proj）
相对位置偏置（relative bias） 在 attention 分数上加一个只与「相隔多远」有关的可学习标量 较好 T5 文本编码器
旋转位置编码（RoPE） 把 Q/K 的每两维看成复数平面，按位置角度旋转 好，可扩展到多维 Qwen-Image（axes_dims_rope=[16,56,56]）、FLUX（(0,h,w)）、H3 的 MM-RoPE (t,h,w)、Qwen2.5-VL / LLaMA 等 LLM

RoPE 为什么能做成多维：把宽度 D 分成几段，每段负责一个轴（时间 t、高 h、宽 w），每段内部再做一维旋转；于是同一个 attention 里可以同时表达「第几帧、第几行、第几列」。H3 的 MM-RoPE (t,h,w) 和 Qwen-Image 的 [16,56,56] 都是这个思路；0 表示该轴不旋转（FLUX 对文本 token 就用 0）。位置编码的选择会决定模型能不能处理训练时没见过的分辨率或时长，这也是「为什么 1024 训的模型跑 2048 会崩」的常见原因之一。

8. attention 的变体：同一个算式的不同外壳

你已经知道 attention 是 softmax(QKᵀ/√d)·V。实际模型里它的差别只有四处：Q/K/V 从哪来、谁能看谁（mask）、K/V 头怎么共享、Q/K 做不做归一化。

变体 Q / K / V 的来源 mask 用在哪
Self-Attention 同一段序列自己的投影 无（双向，能看全序列） U-Net 的 Spatial Transformer、ViT、DiT 的 norm1 之后
Cross-Attention Q 来自视觉/主序列，K/V 来自条件（文本、参考图） 常按 padding 屏蔽无效文本 token SD 的 U-Net、SDXL、ControlNet、IP-Adapter
联合注意力（joint attention） 两路各自投影后沿序列维拼接，一起做一次 attention，再拆回 按模态边界处理 SD3 / SD3.5 的 MMDiT、FLUX 的 double-stream、Qwen-Image、H3 的单流主干
因果注意力（causal） 同上，但只能看当前及之前的 token 下三角掩码 所有 decoder-only LLM，包括当条件编码器用的 Qwen2.5-VL / Qwen3-VL / CLIP 文本塔
窗口注意力（window） 同上，但只在局部窗口内互相看 窗口掩码，窗口之间靠移动或全局层连通 Qwen2.5-VL 视觉塔、Swin 类视觉主干
GQA（分组查询注意力） Q 有 h_q 个头，K/V 只有 h_kv 个头，多个 Q 头共享一组 K/V 同 decoder-only（因果） LLaMA-2/3、Qwen 系列、H3 的条件编码器与主干（省 KV cache 与显存）
QK-Norm 不算新结构：对投影后的 Q、K 再做一次 RMSNorm/LayerNorm 不变 SD3.5（qk_norm=rms_norm）、FLUX（RMSNorm 作用于 Q/K）

一句话记法：self-attn 是「自己人互相看」，cross-attn 是「问外部条件」，joint attention 是「把两路人拼成一队再互相看」，causal 是「不许偷看未来」，window 是「只看邻居」，GQA 是「几个查询共用一本字典」，QK-Norm 是「先归一化再算相似度」。

11. MoE：每个 token 只走少数几个专家

MoE = Mixture of Experts（混合专家）。做法是把 Transformer block 里的那一个 FFN 换成 k 个并行的 FFN（专家），再用一个小网络（router）给每个 token 打分、只把它送给分数最高的前 top-k 个专家，最后按权重把结果加起来。于是总参数量可以很大，但每个 token 的实际计算量只按 top-k 算。

MoE 层的完整结构 虚线框内是一个完整的稀疏 FFN 层：token → router 打分 → top-k 选择 → 专家计算 → 加权求和，以及配套的负载均衡。

工程影响：MoE 的显存占用看「总参数量」，算力看「激活参数量」；专家分散在多卡时，token 的路由会带来 all-to-all 通信（每张卡同时向其它所有卡各发一份不同的数据：本卡把 token 派发到专家所在的卡，专家算完再发回来），这也是它最难调的部分。写模型卡时要同时标出总参数 / 激活参数 / 专家数 / top-k，只写一个数字会误导读者。并行侧的细节见 并行与调度详解 §4 EP。

用在哪里：Qwen3-MoE、DeepSeek 等开源 LLM；视频侧的 Wan2.2 用「高噪声 / 低噪声专家」的形式做了双专家结构（见 主流视频模型与任务）。注意：SD3、FLUX、Qwen-Image 的图像主干都是稠密（dense）模型，不是 MoE；看到「专家」二字要确认是 LLM 侧还是视频侧。

12. U-Net 整机：同一张图在多个尺度上处理

U-Net 不是“一层卷积”，而是一条带有跳跃连接的多尺度 encoder-decoder。输入是带噪 latent x_t，先经过 Down blocks 逐步降低 H/W、增加通道和感受野；中间的 Mid block 在最低分辨率上处理更大的空间关系；Up blocks 再逐步恢复 H/W，并把对应 Down block 保存的 feature 通过 skip connection 拼接或相加回来。这样低分辨率路径负责全局布局，高分辨率 skip feature 负责边缘、纹理和局部定位。

12.2 SDXL U-Net 内部的“层”

每个 down/up stage 由若干 ResNet block、空间注意力和下采样/上采样组成。ResNet block 通常是归一化 → SiLU → 3×3 卷积，再接时间 embedding 的线性投影并加到特征，随后第二个归一化/激活/卷积和残差相加。Cross-attention 把图像 latent 展平为 query，把文本 embedding 投影为 key/value；因此文本不是在每层重新 token 化，而是通过 K/V 调制视觉特征。U-Net 的 skip feature 让高分辨率局部细节回流到 up path。

先看图像公共模块详页 →包含 VAE、条件、采样和通用任务接口再看 SD3/MMDiT 逐模块结构 →双流、联合 attention、输出头和 LoRA

模型特色预告：SD3 把文本流和图像流分别投影后进行多模态联合 attention；FLUX 常见结构是先处理 image/text 双流、再进入单流 blocks；Qwen-Image 使用自己的多模态 Transformer 与图像/编辑条件路径。它们共享“latent → token → Transformer → patch 更新”的接口，但不共享层数、文本编码器、参数名或训练目标。请分别进入 SD3 详情、FLUX 详情、Qwen-Image 详情，不要把这里的共同骨架当成三者的完整实现。

13. DiT / MMDiT 整机：不是一个神秘模型名

DiT 是 Diffusion Transformer 的缩写，意思是“用 Transformer 作为扩散/流生成的主干”。它不是 VAE，也不是 scheduler：VAE 负责像素↔latent，DiT 负责在带噪 latent 上预测更新，scheduler/solver 负责根据预测值推进时间步。图像 latent 被 patchify 成 token 后，DiT block 通常包含归一化、attention、条件调制、MLP 和残差连接；MLP 的“升维—非线性—降维”逻辑与上一部 LLM 的 MLP 相同，但具体激活和条件注入可能不同。

13.1 张量级整机图（SD3.5-large MMDiT）

DiT 这一条路线把 U-Net 的卷积骨架整个换掉：不再保留二维网格，而是先把 latent patchify 成 token 序列，之后全部在序列上做 Transformer。以 SD3.5-large 为例，latent 是 16 通道，patchify 2×2 把每个位置的 16×2×2 = 64 个数展平成一个 token，再做 Linear(64→D) 加上位置编码，得到 [B,N,D]，其中 N = (h/2)(w/2)。主干是 N_layers 层同构 block：SD3.5-large 是 38 层、D=2432（38 head × head_dim 64 = 2432）。

MMDiT 的关键在 block 内部：图像流与文本流各自保留一套投影和 FFN（double-stream）， 但在计算注意力时把两条流的 Q、K、V 沿序列维拼在一起，只做一次 joint attention，算完再拆回两条流。它并不是把两个各自独立的网络拼起来——文本 token 始终和图像 token 在同一条序列里参与注意力，只是不进最终的输出头。

scaling factor 到底在做什么：扩散/流主干的加噪公式默认输入是「大约零均值、单位方差」的数据（DDPM 推导里 x₀ ~ N(0, I) 这个假设），而 VAE 编出来的 latent 各通道标准差并不等于 1——SDXL 的 latent 标准差明显小于 1，直接加噪会让信号淹没在噪声里。训练者因此约定一个常数把 latent 的标准差拉到 ≈1：z' = z × scaling_factor，主干与 scheduler 只见到 z'。这个常数是训练时定好的接口，不是可以随便调的超参：用错值（或忘了乘）会表现为「图糊、鬼影、颜色偏移」，而且换个 checkpoint（例如 SD3 的 16 通道 VAE，其 scaling_factor 与 SDXL 不同）必须重新读 vae/config.json。 解码时必须除回去：真实流程是 latents / vae.config.scaling_factor 之后再 vae.decode；只做乘法不做除法是最常见的复现 bug。新一点的实现还有 shift_factor（先减一个偏移再缩放，SD3 的 VAE 就带 shift_factor=0.0609），规则一样：进主干前缩放、出主干回像素前反变换。

还有一个常见变体：ViT 解码器。它把 latent 当作 token 序列而不是特征图，形状链是 z [B,24,T′,H′,W′] → patchify(p) → [B,N,24p³] → Linear(D_vit) → ViT block ×L → Linear(C·p³) → pixelshuffle → RGB。换成 attention 解码可以减少高分辨率下的卷积解码成本，但时间因果性要靠分块、窗口或逐段解码来保证。哪一种解码器被真正使用，只能读 checkpoint 的 VAE 代码，不能从“时间因果 VAE”这个名字推断。

16. 音频 VAE（立体声 waveform VAE，latent 时间率 40 Hz 一类）

为什么有的模型要挂两个甚至三个文本编码器：不是堆料，而是三件事各缺一半。① 输入长度：CLIP 系列只接受 77 个 token，长 prompt 会被硬截断，T5-XXL 能吃到 512 个 token，所以 SD3 / FLUX 用它读完整句子（长描述、画面里的文字，都靠这条）。② 语义容量：CLIP-L（768 维）容量小、对组合语义弱，SDXL 因此再加一个更大的 OpenCLIP-G（1280 维）并把两者沿通道拼成 2048 维，让主干一次看到两种粒度的表示。③ 两种条件的用途不同：序列条件进 attention 的 K/V 负责「画什么」，pooled 向量进 AdaLN 的调制负责「整体风格与气质」——SDXL 额外喂的 added_cond_kwargs（pooled + 尺寸/裁剪参数）就是后者。代价是显存与延迟：编码器越多、越长，循环外的预计算越慢，所以 FLUX.1-schnell 这类少步模型会只保留 T5。

三种常见时空注意力实现

全时空 attention

所有 T'H'W' token 互相注意，表达力强但成本最高，通常只适合压缩后的短片段。

空间/时间分解

先同帧做空间 attention，再对同一空间位置或窗口跨帧做 temporal attention，降低矩阵大小但需要设计信息交互。

窗口与块状上下文

只在局部时间/空间窗口内计算，再靠窗口移动、重叠或全局 token 传递长程信息；长视频常用上下文管理。

条件注入

文本多通过 cross-attention；参考帧可作为 image tokens；音频可能是 cross-attention 或专门的时间对齐模块，具体需看模型代码。

U-Net、DiT、扩散与流匹配

潜扩散先用 VAE 把图像压到更低空间分辨率，噪声过程在潜变量上进行。SD 1.x/SDXL 的 U-Net 在不同尺度处理局部与全局信息，通过 cross-attention 读文本；SDXL 采用更大的 U-Net、双文本编码器与尺寸/裁剪条件。DiT 把潜图切成 patch token，用 Transformer 自注意力与跨模态交互建模；SD3 的 MMDiT 对图像/文本分别投影再联合注意力。FLUX 系列与 Qwen-Image 也采用多模态 Transformer 路线，但实现、编码器与目标各不相同。

经典 DDPM 学噪声/速度/干净样本的估计，再用 scheduler 从噪声迭代到数据。Rectified flow / flow matching 学时间条件速度场，把噪声分布连续搬运到数据分布；推理用数值积分器走若干步。步数、guidance、solver 不可跨家族照抄。Classifier-free guidance 把有条件和无条件预测组合，增大提示遵循但过强会损伤细节/自然度。

为什么分辨率可以变化？

卷积 U-Net 可接受满足下采样倍数的空间网格；DiT 把不同高宽的潜图切成不同数量 patch，配合位置编码或位置插值/重排处理长度变化。VAE 的压缩比、patch size、位置编码范围和训练中见过的长宽比分布决定可用的高宽与质量。支持可变尺寸不等于任意尺寸无限泛化：token 数近似随面积增长，注意力代价、显存、构图与训练分布都会变；有的模型还要求像素数、边长、比例或对齐倍数。

模型怎样真正接收“不固定尺寸”

以潜扩散为例，输入 RGB 的高宽先经过 VAE 固定比例压缩： [B,3,H,W] → [B,C,H/f,W/f]。只要 H/W 满足 VAE 下采样倍数，U-Net 的卷积和下采样路径就能处理新的网格；如果是 DiT，则 patchify 生成新的 token 数 N。因此“支持可变分辨率”通常来自全卷积空间处理或按当前网格动态生成 token，不是把图片拉伸成一个固定向量。实现仍可能增加三类约束：尺寸必须被 VAE/patch stride 对齐；绝对位置编码需要插值或改用相对/旋转位置编码；训练中见过的宽高比和像素面积决定质量与显存上限。

手算一次空间 token

token 数的算法（N=(H'/p)(W'/p)）与 128×128 latent 的算例见 01 · 基础知识 §2，这里只强调分辨率与注意力的关系：宽高各翻倍使 token 约 4 倍、朴素全局注意力矩阵元素约 16 倍，实际耗时还取决于高效内核、局部注意力和模型实现；视频若再增加时间 patch 数，token 继续相乘。这就是「1024 训的模型跑 2048 会崩」的直接原因。

时空 token 与条件

时空 VAE 先在空间和时间下采样；主干可使用 3D patch、空间/时间注意力或全局时空 attention。视频分辨率/帧数变动时 token 数大致随压缩后的 H × W × T 增长，注意力、激活与解码显存都变大。时间位置编码/相对位置、训练片段长度与 stride 限制可泛化范围，因此“理论上可变帧数”不等于无限长、无限分辨率。首帧图生视频把图像编码为条件并约束首段；首尾帧要约束两个边界，中间轨迹仍可能不合理。

常见训练目标是对随机时间步的噪声潜视频预测噪声/速度，使用文本、图像或音频交叉条件；训练集通常切成固定或桶化的短片段，不断采样不同长宽比和帧数。长片由分镜、重叠窗口、参考帧/记忆或视频编辑拼接得到，而非简单把一次采样帧数无限增大。

扩散/流生成

全片段并行迭代去噪，易于时空联合约束；推理计算随采样步数与时空 token 激增。

自回归 / 混合方法

按 token/块/片段续写，便于延长；误差累积与长程一致性仍需额外机制。不能把所有视频模型概括为同一种架构。

视频制作的指标

画质之外，要检查主体一致性、动作物理合理性、镜头与构图、场景文字、口型/音频同步、闪烁、边界接缝和版权/人物授权。先低分辨率/少帧试构图，锁定 seed/参考图/镜头描述后再扩展、超分和配音。视频评价既有自动指标，也须人工盲评特定任务。

资源调度：图像生成与超分可并行分卡；同一视频镜头生成可能独占多卡；把预处理放 CPU/独立 GPU，避免同时抢主生成卡显存。先粗后精、缓存文本 embedding、共享 VAE/权重、复用参考图；记录失败和重试次数。节点社区插件按可执行代码审计，锁定版本，不向未知节点提供私密图像。

通用微调 / 目标、数据与训练

本地微调：先定义要改变什么

不把“模型不会某件事”全部归咎于权重。知识更新优先考虑检索增强；格式/风格/领域行为考虑 SFT；新主体/视觉风格考虑图像 LoRA；跨模型能力压缩才考虑蒸馏。

方法 更新内容 适合与限制
Prompt / RAG 不更新权重；RAG（Retrieval-Augmented Generation，检索增强生成）先把文档库切成片段并建向量索引，推理时按 query 检索出 top-k 片段拼进上下文 事实经常变化、需要溯源；检索质量与切块方式重要；上下文长度与成本随检索量增长
LoRA / DoRA LoRA 是线性层低秩增量（冻结基座）；DoRA（Weight-Decomposed Low-Rank Adaptation）把权重拆成幅度与方向两部分——幅度单独训练、方向用低秩增量更新 低成本适配；容量受 rank 与目标模块限制；DoRA 训练与显存开销略高，低 rank 下通常比 LoRA 稳
QLoRA 4-bit 冻结基座 + LoRA 适配器 省权重显存；量化/算子/精度匹配需验证
全参数 SFT 全部权重更新 数据与算力充足；优化器/激活成本最高
DPO / 偏好优化 偏好样本下优化候选答案排序 需要可靠 chosen/rejected 数据；不是知识注入捷径
图像/视频 LoRA 生成主干部分投影/模块 主体、画风或动作适配；须防过拟合与灾难性遗忘

LoRA 到 QLoRA 的机制

LoRA 的公式、rank 与 α 的含义、以及该挂到哪些层，已在 07 · LoRA 的真实挂载点 里完整讲过，这里只补两点：可训练量从 $dk$ 降到 $r(d+k)$ 是它的成本来源；QLoRA 则是把冻结基座以 NF4 存储，计算时按块反量化，在高精度路径中叠加 LoRA 梯度；双重量化压缩量化常数，paged optimizer 可缓和峰值。不要把“4-bit 训练”误解为 4-bit 参数直接做常规梯度更新。

通用蒸馏 / 教师、学生与轨迹

蒸馏：把教师的行为转给学生

蒸馏不是“把大模型文件压缩”。先决定想复制哪种行为，再选择可获得的教师信号、许可范围和学生容量。

信号 训练目标 代价与边界
响应蒸馏 教师生成答案，学生做监督交叉熵 SFT 最易本地实现；只学到采样出的结果，继承教师错误
logit / KL 蒸馏 温度 T 的软分布；常用 $T^2\cdot\mathrm{KL}(p_{\text{teacher}}\,\|\,p_{\text{student}})$ 需访问教师 logits；tokenizer/词表不同需对齐或改方法
特征/层蒸馏 中间 hidden state / attention / 表征匹配 层宽不同需投影；训练与教师运行时开销高
偏好/在线蒸馏 教师评分、比较或生成中纠正学生样本 易出现选择偏差与奖励漏洞；需要独立评测
扩散步数蒸馏 教师多步轨迹压到少步生成器 图像/视频专用，如 progressive/consistency 路线；不是语言 SFT

按领域落地：教师给什么，学生学什么

蒸馏的共同问题是“教师信号怎样变成学生的可计算目标”，但语言、图像和视频的信号形状不同：语言常见 response/logits，图像常见某个时间点的 noise/v/velocity，视频还要保留时间和跨模态对齐。先确定教师输出，再设计存储格式和损失。

本地最小实验

  1. 选择许可允许该用途的教师、可装入硬件的学生；用 30—100 条训练问题与 20 条独立测试问题先试。

  3. 把 prompt/response 转成学生 chat template，对学生做 LoRA/QLoRA SFT；同时跑不蒸馏的基座、直接提示和更小模型的基线。
  4. 保留集逐题比较准确率、格式、幻觉、拒答、延迟、显存；在任务漂移样本上复测，再决定是否扩量。

验证实验 / 质量、成本与风险

四个必须亲手做的实验

每次只改一个变量，保留配置和结果。能解释负结果，比把工具全部跑起来更重要。

实验 A · 量化质量曲线

选一个有 BF16、8-bit 和 4-bit 同基座修订的模型；整理 50—100 道自己的任务题。固定 prompt 与采样参数，逐精度记录正确率、拒答/格式率、首 token、token/s 与峰值显存。验收：能说明哪类错误是量化引入，哪类本来就存在。

实验 B · 并行拐点

在同一机器测 1 卡、2 副本、TP=2（若支持）。请求矩阵至少覆盖短/长输入与低/高并发，记录 P50/P95 延迟及总吞吐。验收：解释通信开销何时超过分摊收益，给出本机推荐部署方式。 并行实验的具体协议（先单卡基线，再依次加 DDP / TP / FSDP，每次只改一个维度）见 实验 · 多卡通信与拓扑验收，这里只保留与本书其它实验一致的验收标准。

实验 C · 图像/视频工作流

以同一主题制作 4 张分镜图与 2 个短镜头。固定 seed、参考图、尺寸、模型 revision；比较文生图、图生图、局部编辑；视频检查身份、运动和首尾帧接缝。验收：保存节点图、参数与每次失败原因。

实验 D · 适配与蒸馏消融

基座 zero-shot、基座 + RAG、LoRA SFT、教师直接回答、学生蒸馏五组使用相同保留集。记录每组数据成本、训练时间、模型大小、P95 以及人工盲评。验收：能证明训练确实优于更便宜的替代方案。
