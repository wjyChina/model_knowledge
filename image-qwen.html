模型详解 D / Image Foundation Model

Qwen-Image：MMDiT 类主干、可变分辨率与编辑的双重编码路径

Qwen-Image 是面向文生图和图像编辑的图像基础模型。技术报告说明它使用 Qwen2.5-VL 作为条件编码器、MMDiT 作为主干，并用多任务训练（T2I / TI2I / I2I 重建）对齐两者 latent；本页把“Qwen-Image 类 DiT”展开成可追踪的 顺序数据流，并明确它不是 SD3 或 FLUX 的复制品。本页引用的形状来自该 checkpoint 的 transformer/config.json 与 vae/config.json：60 层、24 heads × head_dim 128、joint attention 维度 3584、in_channels=64、out_channels=16、 patch_size=2、VAE z_dim=16。

2. 文本条件：为什么能处理长文本和图像内文字

模块 输入 输出 作用
processor/tokenizer prompt string input_ids、attention mask 把中文/英文切成模型可处理的序列
文本 encoder input_ids [B,Ntxt] hidden [B,Ntxt,Dt] 或 pooled 保留词序、语义和文字排版指令
condition projection text hidden transformer 使用的条件宽度 对齐文本和图像 stream 的表示空间
joint attention text + image tokens 跨模态 context 让图像 token 读取文字、布局和属性

复杂文字渲染不是单独的 OCR 层就能解释。它来自训练数据（报告描述了大规模采集、过滤、 标注、合成与平衡的数据管线）、条件表示、图像 token 的空间位置和主干学到的字符布局能力；报告还说明训练采用由简到繁、逐步扩展到段落级描述的 课程式策略。工程上要注意两点：encoder_hidden_states_mask 会把文本 padding 屏蔽在 attention 之外；文本条件与图像 token 处在同一序列空间，因此文本 token 数会直接增加 attention 的序列长度。评估时要分别检查短词、 长句、中文、数字、字体结构和精确复制，不能只看画面风格。

本 checkpoint 的事实：VAE z_dim=16；pipeline 的 _pack_latents 把 [B,16,H′,W′] reshape 成 [B,(H′/2)·(W′/2),64]；transformer 配置为 in_channels=64、out_channels=16、 patch_size=2；RoPE 使用 axes_dims_rope=[16,56,56]，与 attention_head_dim=128 对齐。1328×1328 时 H′=W′=166， N_img=83×83=6889。这些数值随 checkpoint 变化：不同版本（Edit / Edit-2509 / 后续 2512 版本）必须重新读 config.json，不要看到“MMDiT 类”就套用 SD3 或 FLUX 的 packing。

6. 为什么 Qwen-Image 可以输出不同分辨率

目标 height/width 进入 pipeline 后，先决定 VAE latent 网格，再按 2×2 打包决定 image token 数。Transformer 可以在不同序列长度上运行，RoPE 用坐标而不是固定参数表表达二维位置，因此 1328×1328、1664×928、928×1664 等比例可以使用不同数量的 token。可变尺寸有四个边界：VAE/pack 对齐、训练数据分布、attention/激活显存、官方建议尺寸与质量阈值。

尺寸换算的通用公式

若空间压缩因子为 f、latent patch 为 p，则 H'=H/f、W'=W/f、Nimg=(H'/p)×(W'/p)。这只是计算 token 的通用关系；Qwen-Image 的实际 f、p 和 packing 必须从配置读取。

“支持可变分辨率”不表示任意超大尺寸都能保持文字和构图质量。显存大致随 latent/token 数增加，朴素全局 attention 的 token pair 更快增长；生产时应保存尺寸、seed、模型 revision 和 scheduler 参数。

7. Qwen-Image / Edit LoRA：主干和编辑条件的微调边界

原型阶段通常冻结 VAE 和文本 encoder，在 QwenImageTransformer2DModel 的 attention q/k/v/out、MLP projection，以及特定 condition projection 上挂 LoRA。Edit 任务还要保证源图、指令、mask/区域标注的配对质量；只训练主干却用错误的 mask，会学到错误的编辑边界。

候选模块 输入 LoRA 修改的输出 用途
attention q/k/v 文本/图像 token Q/K/V 概念、文字与图像条件对齐
attention out context hidden update 跨模态融合和残差强度
MLP / ff projections token hidden 通道非线性变换 风格、纹理、概念偏移
condition projection image/mask/pooled condition 进入主干前的条件表示 编辑结构、区域和参考图关系

Qwen-Image / Edit 需要什么数据

Qwen-Image 的文字和编辑能力决定了数据不能只有“图片 + 风格词”。文生图样本应有自然语言 caption、精确画面文字、文字区域和语言/字体信息；Edit 样本必须是 source、target、instruction 的严格配对，局部任务再加入 mask。尺寸、裁剪、长宽比、来源许可和 split 必须写入元数据，并按主体和原始文档去重。

任务 数据字段 训练方式 验收指标
概念/风格 image、caption、style/subject、尺寸、许可 冻结 VAE/text encoder，主干 attention/MLP LoRA 主体、风格、长宽比和文字泛化
精确文字 image、transcript、language、font、text_boxes 扩大 joint attention/MLP target，混入通用 caption 防遗忘 字符准确率、位置、字号和长句
Edit / mask source、target、instruction、mask、reference_images 主干 LoRA + condition projection；mask 语义与 pipeline 保持一致 编辑区域成功率、非编辑区保持和指令遵循

Flow/velocity 训练仍是随机时间点的 latent 目标；小数据优先 rank 4—16、低学习率、尺寸桶和短实验，先只训主干 LoRA，不要同时解冻 VAE 与文本编码器。固定一组中文/英文长短文字、未见主体、不同宽高比和编辑 mask 做回归，并记录模型 revision、patch/packing、scheduler、rank/alpha 与 target_modules。

官方仓库还提供 Qwen-Image Edit / Edit Plus pipeline 与多卡 API server 示例。 结构核验的优先顺序是：Qwen-Image Technical Report（arXiv:2508.02324） → Qwen-Image 官方仓库（Edit / Edit-Plus 的实现入口）→ Diffusers QwenImageTransformer2DModel 文档 → 实际 checkpoint 的 transformer/config.json 与 vae/config.json。版本、显存、许可证与 pipeline 参数以官方仓库当前说明为准。

论文与 checkpoint 的分工：技术报告可证实来源图分别送入 Qwen2.5-VL 与 VAE、多任务训练含 I2I 重建、以及课程式文本渲染训练策略； 报告不能证实某个具体版本的层数、打包方式、mask 支持或默认步数，这些必须读 config 与 pipeline 代码。未公开：训练数据规模、各任务 loss 权重、时间采样分布与完整超参；Edit 各版本的功能差异以 pipeline 签名与官方示例为准。
